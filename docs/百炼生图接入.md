# 百炼 qwen-image-2.0 接入统一后端

应用已移除旧本地模式，百炼与 Mock、ComfyUI 共用 PostgreSQL / RabbitMQ / Redis / Celery 架构。
旧 `npm run bailian`、`start:bailian` 和 `SWARMUI_IMAGE_API_KEY` 启动方式已退役；已有本机配置不会自动读取、导入或删除。
先按 [统一部署手册](runbooks/production-cutover.md) 配好数据库、身份、HTTPS 与工作区权限。

## 固定模型路由

在不含密钥的 provider-routes.json 中配置 image 路由；路径通过 `.env` 的 `AIVERO_ROUTES_FILE` 挂载给 API。

```json
{
  "image": {
    "provider": "cloud",
    "cloudVendor": "aliyun",
    "cloudBaseUrl": "https://YOUR_WORKSPACE_ID.cn-beijing.maas.aliyuncs.com/api/v1",
    "cloudModel": "qwen-image-2.0",
    "configVersion": "bailian-v1",
    "credentialRef": "bailian-image-v1"
  }
}
```

以上 endpoint 格式对应本项目已有的百炼适配；实际地址、地域与模型授权以你的服务配置为准。
不要用 OpenAI compatible-mode 地址代替这里的原生协议地址。

## Worker 凭据与产物下载

在自己的编辑器中创建独立凭据文件，将 `bailian-image-v1` 映射到 `imageApiKey`，并用
`AIVERO_CREDENTIALS_FILE` 指向其绝对路径。该文件只挂载生成 Worker，不进入路由文件、浏览器或 Git。
保留尚未结束任务引用的凭据版本，避免任务无法查询或下载。

产物下载采用独立受限 HTTP 客户端，需用 `AIVERO_ARTIFACT_ORIGINS` 配置实际图片服务的精确 HTTPS origin，
多个 origin 以逗号分隔。不要用通配符或关闭校验。没有配置允许的产物 origin，任务不能自动下载外部文件。

## 启动与验证

```bash
docker compose config --quiet
npm run stack:up
```

打开已配置的 HTTPS 工作台，登录并进入已授权工作区。模型列表来自固定路由，无网页密钥设置入口。
确认目标模型和参数后再提交单次生成；真实调用可能产生费用。Mock 或配置加载成功不代表真实供应商已验收。
生成受理后返回 Job，Worker 分阶段执行并保存产物；SSE 更新状态。上游提交结果不确定时进入 unknown，
应先对账原任务，不要通过不断重新提交规避不确定状态。

本次运行模式统一没有调用真实百炼服务。旧评测与兼容测试仍在隔离沙箱中验证协议，不能替代真实模型验证。
