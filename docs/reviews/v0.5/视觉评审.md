# v0.5 独立视觉评审

评审对象：`docs/产品效果-创作平台-v0.5.html`，以及 `visual-src` 下的页面、样式和呈现逻辑。按本轮新视觉独立判断，不继承 v0.4 的通过结论。已读 impeccable 的 `craft-floor.md`。

本评审是截图与源码的视觉分项；浏览器功能验证由主任务执行。已看 1280×720 的介绍页、工作台、空列表、有内容列表、编辑器、蒙版态，以及 390×844 的手机介绍页、工作台和列表。最终重新打开工作台、编辑器、蒙版三张更新截图确认修正，未沿用其旧截图。

## 视觉判断

这版已经有明确方向：暖白页面、低饱和摄影、深绿操作色和有分量的中文标题形成了连贯的视觉语言。介绍页的不等宽三图构图成立，建筑主图给首屏一个清楚的焦点；标题、说明和主要按钮有主次，没有靠堆叠卡片或装饰制造完成感。空列表的大图欢迎页也能让第一次创建的动作被直接看到。

最终版将工作台欢迎区压缩到 220px，使最近画布的图片、名称和打开入口进入桌面首屏；手机工作台收起欢迎区配图，也保住了最近画布的完整展示。编辑器把操作文字提升到 12px、输入与对话正文提升到 14px 后，读写尺度更适合实际使用，蒙版工具栏保持完整，没有遮住其操作名称。

**结论：本轮视觉分项通过，可交付原型展示。** 当前覆盖范围内没有保留必须处理的视觉问题。审美判断是克制、自然、连贯的创作工具方向；首页表现最完整，内部页面已保持同一气质并具备清楚的操作层级。这个结论针对本轮截图与源码，不替代用户对视觉方向的最终偏好，也不扩展为生产可访问性或全交互验收。

## 本轮问题闭环

1. **已关闭 · 原 P1：编辑器主要操作和输入内容偏小。** 初始截图中，缩放、选图工具栏、蒙版工具、生成按钮多数为 10px，输入正文为 12px。最终源码和截图确认：主要操作 12px，输入与对话正文 14px；蒙版工具栏仍完整显示，输入区没有被挤压。较低层级的辅助信息不再与核心操作争夺阅读空间。

2. **已关闭 · 原 P2：工作台首屏看不到最近画布的名称与打开入口。** 初始宣传横幅为 312px 高，最近画布从约 y=600 开始。最终有文档时桌面横幅降为 220px，最近画布图片从约 y=507 开始，打开入口及名称完整可见；手机欢迎区隐藏配图后，最近画布及名称也进入 390×844 首屏。空状态保留大图欢迎，区分了首次访问与回访。

3. **已关闭 · 原 P2：画布封面随列表排序变化。** 初始 `visualDocCard(d, index)` 使用 `index % 4` 选取演示封面。源码已改为对文档 ID 做稳定哈希映射，同一文档封面不再跟随列表位置变化，并保留“演示封面”说明。

## 已确认与边界

- 工作台重复两层品牌导航的旧问题已修正，不计入未解决问题。
- 手机介绍页的中文大标题完整，主要按钮可见；工作台和画布列表未见明显横向裁切、标题溢出或主要操作被遮挡。
- 图片被明确标为展示素材，蒙版标为交互示意；本评审不要求用真实生成结果或真实识别来增加视觉可信度。
- 对比度抽查：辅助色 `#597153` 对画布底色 `#f0f3eb` 约为 **4.79:1**；`#566e52` 对 `#edf1e7` 约为 **4.89:1**；白字对主要按钮 `#286b50` 约为 **6.35:1**。这些样本达到普通文字 4.5:1 的基准，不能据此宣称所有状态均符合可访问性要求。
- 本分项未操控浏览器、未调用生成模型、未修改 UI 源文件或生产代码。只记录有截图或源码依据的问题；交互通过结论由主任务的功能验证负责。
