# 暗色展厅与动效检查

2026-09-09。用户反馈介绍页主题仍不好、首屏突然出现开始操作区很奇怪，并要求讨论、加入动效。

## 讨论与本轮实现

设计角色认为，满屏影像、白色启动卡、浅灰功能区缺少连续的视觉语言；体验角色指出，白卡外形接近输入区，且与顶部创作入口重复。动效角色发现原先直接替换图片再从固定透明度开始动画，连续切换会产生跳变。

本轮据此实现暗色影像展厅：深炭灰背景、暖白文字和按钮，让照片提供色彩。删除首屏白色启动卡，把主入口集中在顶部；标题靠左分两行，作品切换与说明放左下。图库、真实编辑器截图和开放式助手步骤延续同一背景语言。

该方向是本轮可供用户评审的实现，不表示已获得用户对具体风格的确认。工作台、画布列表和编辑器主题范围未扩展。

## 动效

| 场景 | 目的 | 实现 |
| --- | --- | --- |
| 首屏初次进入 | 建立作品与标题层级 | 背景 1000ms 轻缩放至静止；标题两行 620ms 上移淡入，错开 80ms |
| 主动切换作品 | 连接前后画面 | 三层图片先 decode，再以 CSS opacity 650ms 交叉淡化；请求序号防止旧加载覆盖新选择 |
| 浏览作品与画布 | 展开可见内容 | IntersectionObserver 首次进入时播放；四幅作品 480ms、间隔 55ms；实际界面图 620ms 整体进入 |
| 离开、后台、减少动态 | 保持稳定状态 | 取消动画与观察器，使待解码请求失效；返回不重播首屏；减少动态下直接显示最终状态 |

采用现有 `cubic-bezier(.22,1,.36,1)`，只使用 CSS 与原生 WAAPI，未引入动画库。默认内容可见，动效不阻止点击。没有自动轮播、循环漂浮、强制滚动或虚构生成进度；悬停缩放限定精细指针与支持悬停的设备。

## 验证结果

- 1280×720 检查首屏、图库、画布与助手；390×844 检查首屏、双列图库与大图弹层，页面内容宽度为 390px。临时视口已重置。
- 快速连续点击空间、花卉后，最终 active 与 `aria-pressed` 均为 flower；读取到三层不透明度正在向最终值连续过渡，过渡时间为 0.65s。首屏不存在 `.landing-launch`。
- 大图可正常打开；Escape 关闭，焦点恢复到花卉触发按钮。
- 顶部“开始创作”进入工作台，介绍页隐藏并设置 motionPaused；浏览器后退恢复 `#create-images`，介绍页可见、分区顶部 20px。当前浏览器错误日志为空。
- 外层与 iframe 脚本语法、模板占位符、ID 与介绍链接另做构建检查。独立源码复核覆盖加载乱序、离开取消、动态 reduced motion、后台与重新进入，见 [主题与动效复核](./主题与动效复核.md)。
- 独立视觉结论为 **ship，可交付讨论原型**，见 [暗色展厅视觉评审](./暗色展厅视觉评审.md)。静态截图不作为动画帧率或性能剖析证据。
