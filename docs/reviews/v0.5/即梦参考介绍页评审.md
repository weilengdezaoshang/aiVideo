## 结论

视觉方向与参考目标一致，仍使用 aiVideo 品牌。已看桌面首屏、图库、放大弹窗、画布介绍、助手介绍，以及 390 × 844 手机首屏、图库和弹窗。没有发现标题或主要操作裁切、内容重叠、按钮被遮挡等交付阻碍。初审发现的 1 项路由问题已修复并通过下述源码执行复核；本评审范围内没有未关闭的交付阻碍。主任务的浏览器证据另见[介绍页检查](./即梦参考介绍页检查.md)。

## 已关闭 P2：从编辑器后退到介绍页锚点时，介绍页仍被隐藏

位置：[product-shell.html](./visual-src/product-shell.html) 的 `hashchange`、`request` 与 `reveal`。

路径：在介绍页点击“图片创作”，地址变为 `#create-images`；点击“体验四方向画布”进入 `#editor`；浏览器后退到 `#create-images`。

初审时，该监听对三个介绍页锚点直接 `return`，不会向 iframe 请求返回 `intro`，也不会更新容器显示。因此地址已指向介绍页分区，页面仍停留在编辑器。`#create-canvas` 与 `#create-assistant` 同样受影响。问题已通过实际 shell 脚本执行确认。

修复后，非介绍页收到分区锚点时调用 `request('intro', location.hash)`，保存目标 `introAnchor`，并通过 iframe 既有 `go()` 离开保护处理导航。只有收到 `product-route: intro` 才显示介绍页并滚动至分区；保留已到达的锚点，不额外写入 `#intro`。初始化前的待处理请求同时保留页面与锚点。

复核使用 Node VM 执行最新 shell 脚本，以及真实 `product-extension.js` 的 `go()`、`render()`、`actionClick()` 和原型的基础 `actionClick()`；仅 DOM、存储与窗口消息队列使用最小替身。以下 5 个场景均通过断言：

1. `#create-images`：返回介绍页，隐藏产品区，滚动到图片分区，保留锚点，无额外历史写入。
2. `#create-canvas`：返回画布介绍分区，显示与历史行为同上。
3. `#create-assistant`：返回助手介绍分区，显示与历史行为同上。
4. 保存失败时选择“留在画布”：保持编辑器显示，恢复 `#editor`，不滚动介绍页；随后普通“产品介绍”导航不会复用已取消的旧锚点。
5. 保存失败时选择“重试保存并返回”：确认保存后显示介绍页，并返回最初请求的助手分区。

这些是实际源码执行的消息/状态断言，不等同于浏览器渲染或原生历史事件测试。

主任务随后记录的浏览器证据：从 `#editor` 进行同文档导航到 `#create-images` 后，`intro.hidden=false`、`product.hidden=true`，目标分区顶部为 20px；助手区、图库弹层的示例入口与工作台入口均可达。该结果支持修复后的真实页面显示与入口行为；本分项没有亲自控制浏览器，也没有把同文档导航描述为原生后退按钮实测。完整记录见[介绍页检查](./即梦参考介绍页检查.md)。

## 其余核对结果

- 真实表达：首屏和图库弹窗明确“非本产品生成结果”；四图下方说明照片并非同一提示词生成；画布截图标明“当前产品原型界面”；助手卡片标明流程示意，最终操作等待用户确认。页脚说明本机演示、不调用生成模型，展示照片来源可展开查看。
- 可访问性基础：场景按钮有可访问名称及 `aria-pressed`；图库按钮可通过原生按钮进入 `dialog`，弹窗有标题关联与关闭按钮，关闭事件恢复触发按钮焦点；图片具备替代文本；场景动画和图库缩放均响应减少动态效果偏好。键盘行为仍以主任务实测为准。
- 入口与构建：工作台按钮请求 `workspace`，体验入口请求 `example`，后者由既有状态机打开示例画布；文档链接对应文件存在；构建将图片、字体、原型和脚本嵌入输出，并断言没有遗留模板占位符。
