# 产品页面补充与检查

用户反馈：原交付缺少介绍页与独立产品效果 HTML。本次补充 [产品介绍与交互原型](../../产品效果-创作平台-v0.4.html)，并在原 [交互 PRD](../../交互PRD-创作平台-v0.4.html) 顶部和流程演练区加入入口。

## 补充页面

| 页面 | 可见内容 | 可以完成的操作 |
| --- | --- | --- |
| 介绍页 | 产品用途、流程预览、三步说明、首版范围 | 切换四方向/蒙版/派生预览；进入工作台；打开示例画布；阅读 PRD |
| 工作台 | 画布主入口、最近画布、图片与视频入口说明 | 进入我的画布、打开最近文档、查看视频范围说明 |
| 我的画布 | 空态、新建、已有文档卡片 | 新建并命名，打开文档，返回工作台 |
| 编辑器 | 全窗口画布、四工具、底部输入、右侧对话 | 四图模拟、选图、蒙版、显式抠图、相邻结果、引用和恢复演练 |

入口浏览不创建文档。“查看示例画布”是明确的本机示例操作，直接准备一个包含四张候选的示例文档，不调用模型。演示控制默认折叠；有任务等待时显示“查看本次模拟结果”，避免卡在加载状态。失败、未知结果和保存失败开关保留在演示控制内。

介绍页中原四格宽度不随派生插入而变小，新增结果通过预览行自身的横向滚动查看。生产编辑器保留前轮固定尺寸与派生链规则。页面风格延续黑白灰低保真，没有新增商业承诺或生产能力声明。

## 本轮验证

通过本地 HTTP 静态预览，实际操作并读取页面状态：

1. 介绍页切换派生预览，说明与结果数量同步变化。
2. 进入工作台显示概览；再进入列表显示空态，没有自动创建文档。
3. 新建并命名“产品效果体验”；生成时四个占位同时出现，点击模拟响应后整组呈现。
4. 选图进入识别，模拟响应后进入蒙版；再次点击“抠图”并送达模拟响应，新增一个透明示例对象。
5. 返回列表保留名称与创意组；产品导航可返回介绍页。
6. “查看示例画布”直接打开咖啡店示例文档，包含同组四候选与对话预览。
7. 演示控制可以展开，默认隐藏的模拟开关可访问。
8. 两份 HTML 的外层及 iframe 脚本通过 Node 语法检查；本地链接、重复 ID、构建占位符检查通过。

视觉证据由独立复验记录限定范围：[产品页面视觉复验](./09-产品页面视觉复验.md)。介绍页、工作台与编辑器截图是实际浏览器截图；390px 修订前截图仅用于说明初始窄屏布局，不能充当最后一次尺寸修正后的像素验收。最终窄屏状态与完整编辑器移动端行为不作全面通过声明。

自动化浏览器禁止访问 `file:` URL，因此本轮直接文件打开未验证，没有绕过该限制。HTML 本身不引用外部脚本或模型服务，运行验证通过的是本地 HTTP 方式。生成、上传、视频和下载仍遵循前轮演练的明确模拟边界；不是生产功能验收。

## 维护方式

原型复用 `prototype.html` 的状态逻辑，通过 `product-extension.css` 与 `product-extension.js` 添加工作台和全窗口适配；`product-shell.html` 提供介绍页及外层导航。执行 `python3 docs/reviews/v0.4/interactive-src/build.py` 同时生成产品 HTML 和交互 PRD，避免维护两份生成/蒙版状态机。

介绍页为本轮新增建议；PRD 与技术方案同步补充页面、地址和实施工作包。此前“工作台默认列表”的建议在补充稿中改为概览→画布 Tab→列表。产品源码、配置、运行数据与原有未提交修改均未改动。
