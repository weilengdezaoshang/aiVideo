用户反馈后的补充：[介绍页与独立产品原型](../../产品效果-创作平台-v0.4.html)；具体新增页面与检查范围见 [页面补充检查](./08-产品页面补充与检查.md)。

- [交互 PRD](../../交互PRD-创作平台-v0.4.html)：一个自包含 HTML，含总览、流程演练、完整 PRD、技术方案、五角色讨论、验收与决策六部分。
- [PRD 源文档](../../PRD-创作平台与画布Agent-v0.4.md)：范围、页面、操作规则、Agent 用例与 A01–A16 验收。
- [技术方案](../../技术方案-创作平台与画布Agent-v0.4.md)：代码复用、数据与 API、四图调度、蒙版、Agent、事件恢复、Python 迁移及重点实验。

HTML 无外部脚本或模型请求，可以直接用桌面浏览器打开；浏览器对 `file:` 页的存储策略可能不同，建议通过本地静态服务预览。评审备忘和演练分别存在当前浏览器、当前来源的 localStorage；更换浏览器或端口不会自动同步。JSON 下载只导出评审备忘，不是产品画布文件。

可维护源文件在 [interactive-src](./interactive-src)。修改 PRD、技术方案或角色文档后，在仓库根目录执行 `python3 docs/reviews/v0.4/interactive-src/build.py` 重新生成 HTML；脚本仅使用 Python 标准库。wrapper.html 是阅读容器，prototype.html 是演练。此处是文档构建脚本，没有新增产品后端。

## 真实浏览器检查

| 操作 | 观察结果 |
| --- | --- |
| 工作台→画布列表→新建 | 列表空态可见；进入列表未创建文档，新建后进入编辑器 |
| 命名→返回列表 | 修复输入持久化后，列表显示名称“四方向与抠图评审” |
| 生成一组 | 四个占位同时出现；送达模拟成功响应后同时显示四个结果及右侧四格预览 |
| 手动抠图 | 第一次点击进入识别；响应后只有蒙版，没有透明结果；最终按钮单独提交 |
| 抠图生成失败→返回蒙版 | 仍为四个原结果，蒙版保留，返回编辑不自动重新生成 |
| 再次显式提交→成功→浏览器刷新 | 新增一个透明示例对象，计数 4→5；刷新后仍为 5，没有重复插入；候选槽仍为四个 |
| Agent 引用→发送明确需求 | 引用显示在输入区；自动进入一次准备，未要求额外准备按钮；收到响应后等待用户 |
| Agent 等待时刷新 | 保持同一蒙版、等待提示与对象数，没有自动生成 |
| 蒙版保存失败→保留草稿退出→检查主体选区 | 能恢复原草稿；不会重做识别或创建透明结果 |
| 四图部分失败→另生成一组 4 张 | 旧组保留两张成功结果和两个失败槽；新建第二组，不覆盖旧成功图；界面说明新调用可能产生费用 |
| 新组结果待确认→刷新→查询响应 | 保留相同组标识与未知状态；模拟后续响应落到原组，没有额外创建结果组 |
| 保存失败→返回 | 显示保护对话；重试保存并返回后文档仍在列表 |
| 验收筛选 | 搜索“蒙版”显示 A07/A08，共两条；已修复隐藏行仍占布局的问题 |
| 勾选与决策备忘→刷新 | 一条勾选、选项、临时备注均恢复；检查后通过 UI 清空临时审阅选择，没有替用户批准方案 |

以上通过真实浏览器点击、键盘和刷新检查，但响应来自评审控制台模拟，不证明生产 API、真实模型或数据库恢复通过。

## 静态检查及限制

最终校验包含：外层和 iframe 两段脚本的 Node 语法检查；HTML 重复 ID、构建占位符与本地链接；技术方案 SQL DDL 在内存 SQLite 执行，以及三段 JSON 解析。DDL 创建 19 张业务表，SQLite 另建内部 sequence 表。这些检查只说明草案语法和引用有效，不说明领域约束已经完整实现。

演练未完整实现生产规则：控制点不执行真实变换；视频、上传和下载为有说明的状态示意；没有真实 LLM、媒体文件、网络队列、服务端 revision、SSE 或双标签协调。演练的文字编辑、拖动和笔刷不是完整编辑器验收；未将极端缩放、全部键盘行为或长时间性能标为通过。真实能力与故障注入按技术方案 S1–S11 后续执行。
