## 核心流程与状态

### 入口与保存

```text
工作台 → 画布 Tab → 列表读取 → 空态 / 已有列表 / 读取失败
  → 新建（一次创建意图）→ 创建中 → 已确认 ID → 稳定编辑器地址
                                ↘ 响应未知 → 查询原创建意图 → 已存在 / 明确失败
已有卡片 / 稳定地址 → 读取文档、会话、任务 → 恢复编辑器
编辑 → 未保存 → 保存中 → 已保存
                     ↘ 保存失败 → 留在画布 / 重试保存 / 明确放弃未保存修改
返回 → 先完成保存 → 我的画布；已提交后台任务继续属于原画布
```

| 当前状态 | 触发动作及前置条件 | 界面反馈 | 后续状态 | 失败恢复 |
| --- | --- | --- | --- | --- |
| 列表加载/错误 | 点击新建；创建服务可用 | 新建按钮显示创建中，同一动作所有入口同步禁用 | 成功后进入唯一 ID 的画布 | 网络不明先查原请求；明确未创建才重新提交 |
| 编辑器空态 | 本地上传/资产导入成功 | 新对象位于可视区域，选中新对象；不插入虚构 Agent 回复 | 待保存 | 文件失败保留页面与输入，取消不加对象 |
| 可编辑 | 修改名称、对象、位置或尺寸 | 顶栏先标未保存，短暂防抖后保存中 | 确认最新修改版本已写入后才显示已保存 | 失败保留本地变更，不回滚用户当前画面 |
| 存在未保存变更 | 返回画布列表 | 先尝试保存；保存成功直接返回 | 列表刷新名称、封面和更新时间 | 保存失败显示留在画布/重试/放弃未保存修改，默认焦点留在画布 |
| 已提交任务 | 返回、刷新、重新打开 | 返回无需把生成等完；重开显示查询原任务 | 恢复对应原组或新结果 | 断线显示状态待确认；不把无事件等同于失败 |

建议：应用首次默认工作台的画布 Tab；卡片打开后恢复该文档最后视口。重命名采用顶栏内联输入，Enter 保存、Esc 还原，空白名称回到“未命名画布”；名称长度上限由前后端共同确定。列表加载不必阻塞与列表内容无关的新建，但创建请求必须独立反馈。

### 四图生成

```text
输入需求 → 展示固定“4 个方向 × 每方向 1 张” → 发送
  → 确认提交 → 一个四槽结果组 → 四槽同时生成中
    → 整组成功：4 张同时替换四个占位，显示 4/4
    → 整组终止但部分有效：保留有效图 + 原失败槽，显示部分完成
    → 整组失败：四个失败槽 + 原需求 + 原因
    → 状态未知：查询原任务，暂不允许重新发起同一请求
部分完成/失败 → 用户点击“重新生成一组（4 张）” → 新任务、新组；旧组保留
```

1. **已确认**：一次用户提交是一个任务和一个结果组；四槽同批进入生成中，不能用逐张排队冒充并发。无真实进度时只显示不定进度提示。
2. **建议**：UI 可先展示四槽“正在提交…”，服务端确认该组提交后四槽同时进入生成中。若供应商只能串行，整个能力标为尚未满足四方向要求，不能用 UI 隐藏串行事实。
3. **建议**：服务端可能先收到部分结果，但在整组结束前不对用户逐张揭示“1/4 → 2/4”进度。终态统一显露四张，或明确异常部分完成。完成比例是终态数量，不是耗时进度。
4. **建议**：显示四方向短说明及可展开提示词，让用户知道差异；初版由系统形成方向，不增设四份复杂表单。方向应在提交前固定，刷新不重算。
5. **建议**：首版不做自动补缺；“重新生成一组（4 张）”显式标注数量，在新组关联原组。未来若支持“只补失败方向”，它必须是已定义的修复操作，并保留槽位与尝试历史，不能冒充一轮四图生成已经成功。
6. **建议**：执行中允许继续编辑输入草稿，但同一画布不同时启动多个修改画布的 Agent 运行；按钮说明“当前任务完成后可发送”。允许缩放、浏览、非冲突的对象编辑和离开，不锁死整页。
7. **建议**：取消整组时显示“正在请求停止”，以服务端确认结果为准；若供应商不可取消，只允许“停止后续步骤”，已提交生成仍可能完成。部分有效结果与执行记录保留，不宣称取消已免除调用。

### 抠图与派生结果

| 当前状态 | 触发动作 | 前置条件 | 界面反馈与后续状态 | 失败/退出 |
| --- | --- | --- | --- | --- |
| 普通图片选中 | 图下工具栏“抠图” | 可读图片与识别能力可用 | 进入该对象蒙版模式；识别中，不产生透明结果 | 原图保留；识别失败显示重试识别/返回图片 |
| 识别中 | 服务返回蒙版 | 源资产版本未改变 | 原图背景可见，主体叠蒙版；进入待确认 | 退出可停止关注或请求取消识别；晚到结果最多存草稿，不自动打开编辑/生成 |
| 蒙版待确认/编辑中 | 画笔、橡皮、撤销、重做 | 有有效蒙版 | 更新草稿；局部蒙版历史与画布操作历史分离 | Esc/退出保存草稿，恢复普通选择；不生成结果 |
| 蒙版就绪 | 蒙版栏“抠图” | 非空有效蒙版、源版本有效、无本次提交在途 | 固定当前蒙版版本与源版本，按钮生成中；锁定此次蒙版编辑与重复提交 | 响应未知查询该次提交；不得直接再次调用 |
| 结果生成中 | 收到有效资产并确认落位 | 任务与对象归属一致 | 源图右侧新增派生图；组内后续项顺延、容器扩展；恢复普通工具栏 | 失败保留已提交蒙版与原图；“返回蒙版”不自动重试 |
| 有草稿 | 再次进入同一源图抠图 | 原资产版本相同 | 显示“已恢复蒙版草稿”，可继续改或重新识别 | 原资产已改变则标注旧草稿不可直接复用，显式重新识别 |

补充默认：

- 蒙版画笔表示“保留区域”，橡皮表示“移除选区”，提供可调笔刷大小；辅助选择未有能力依据时禁用并说明，不假装可用。不得用不透明蒙版完全遮住源图细节。
- 点击其他图片、开导入面板或返回均先退出蒙版并保留草稿；若草稿持久化失败，提示留在编辑/明确丢弃草稿，不能静默丢失。应用刷新恢复草稿但不自动进入生成。
- 结果位置由落位时源对象位置计算；源图在生成过程中移动，结果跟随源图的最新位置。建议派生图依创建顺序紧随源图排列：原图 → 派生 1 → 派生 2 → 下一原方向；四方向编号始终为 01–04。
- 组内水平间距固定为建议值 24 个画布单位；对其他独立组的冲突先明确显示结果及“定位结果”，不在首版自动搬动无关对象。跨组自动避让属于后续能力。
- 源图在生成中被移除时，完成资产保留在本画布会话/资产中，提示“来源对象已移除，结果尚未放入画布”，提供显式加入；不复活源对象。Agent 将此视作“结果已生成、放置未完成”，不能显示全部完成。
- 成功时仅在用户仍停留该次操作且未更换选择时选中新结果；用户正在编辑其他对象时保留焦点，以结果卡和定位操作通知，避免打断文字或蒙版操作。

### 引用对象与 Agent

```text
选图片 → 添加到对话 → 底部可见引用标签 → 输入需求 → 发送
  → 形成方案（引用快照、步骤、次数、结果位置、需用户完成的检查点）
  → 执行方案 → 执行已批准步骤
      ↘ 需要抠图：识别蒙版 → 等待用户 → 蒙版栏“抠图” → 完成该步骤
      ↘ 步骤失败：保留成功产物 → 用户选择重试该步骤 / 结束本次任务
      ↘ 范围变化：返回新方案，不自动加入额外一轮生成
  → 结果资产有效且已持久化放入当前画布 → 完成，显示定位/继续修改
```

以上“执行方案”是**拟议产品交互**，不要求本轮用户授权额外实施。首版 Agent 用例仍由主持收敛，不把示例直接设为已确认功能。

| 时点 | 建议规则 |
| --- | --- |
| 选择图片 | 仅改变画布选中态，不改变已写好的输入引用 |
| 添加到对话 | 引用携带缩略图、名称；点击标签定位对应画布对象；相同对象/资产版本去重，可移除；加入后输入框获得焦点 |
| 发送前 | “这张图”无引用时就地提示添加素材；多引用产生歧义时由可见标签指定目标，不静默挑最后一张 |
| 发送时 | 固定 `canvasId + objectId + assetId + assetVersion`，用户消息保留缩略图和名称快照；发送被服务端确认后清空本次文本和引用，失败保留草稿 |
| 计划展示 | 步骤用用户词汇，比如“生成 4 个背景方向”“把结果放到原图右侧”；显示本计划最多生成几组，哪些步骤需用户接手；引用可见不宣称已完成视觉理解 |
| 执行前 | 检查引用存在/可读及所需能力；对象移动可沿用同资产并采用最新位置，资产替换/删除则暂停请用户更新计划 |
| 执行中 | 可浏览和编辑下一条草稿；不允许新指令静默改写执行中的提示词、素材或数量。需要改变时先停止尚未提交的步骤，再重新规划 |
| 失败后 | 显示明确失败步骤、已完成结果和是否存在未确认调用；只有确认失败且可安全重试的步骤可重试；已有成功步骤不重做 |
| 刷新重开 | 恢复对话、计划、步骤、结果；查询已提交任务可继续接收结果，尚未提交的 Agent 步骤默认不自动续跑 |
| 继续修改 | 结果卡提供“添加到对话”；继续操作从新引用快照开始，不因为聊天中说“再来”就隐式扩大批次数量 |

## 选择、浮层、焦点与键盘

### 命中与模式

| 元素 | 单击/拖动 | 键盘/补充 |
| --- | --- | --- |
| 画布空白 | 单击取消选择；空白拖动平移 | Space 按住时拖动平移；不在文本输入控件内生效 |
| 独立图片 | 单击选中；拖本体移动；控制点缩放 | 方向键微移，Shift + 方向键较大步移；输入焦点内不截获 |
| 生成组标题/边界空白 | 选择整组；拖标题移动整组 | 不显示单图专属抠图；整组不默认提供拆组 |
| 组内图片 | 单击只选该图；仍保留所属组 | 首版横排由组管理，不自由拖散；提示“拖动组标题移动整组”。单图等比缩放后重排后续项，仍维持 01–04 顺序 |
| 图片控制点 | 四角与四边点均等比缩放，最小尺寸受限 | 具体锚点在实现中统一；不擅自变为自由拉伸或裁剪 |
| 文字对象 | 单击选择、双击编辑；编辑中拖拽由文本选择接管 | Enter 换行；Ctrl/Cmd + Enter 完成；Esc 撤回本次文字编辑并结束；新建空文字退出后不保留空对象 |
| 视频对象 | 单击边框/海报选择；拖边框移动；明确播放按钮打开预览浮层 | Enter 打开选中视频；浮层 Space 播放/暂停，Esc 关闭且暂停；首版画布内不自动播放 |
| 蒙版模式 | 图像命中区专用于笔刷/橡皮，不能移动对象 | Ctrl/Cmd + Z/Y 只作用蒙版历史；Esc 保存草稿退出 |

图片缩放和受控组移动是建议，需产品/技术共同确认。若组内拖动自由拆离是必须需求，应另定义来源组关联与再排版，不能靠前端临时行为决定。

### 浮层与按钮

- 普通操作栏与蒙版栏互斥。工具栏基于选中对象屏幕包围盒定位，默认下方居中，保留间距；滚轮缩放只改变对象几何，不缩小工具栏文字/点击区。
- 可用区域排除顶栏、左工具、右对话与底部输入框。横向越界向可用区域内夹紧，长栏内部横向滚动。下方空间不足时优先微调视口使图下工具栏可见；仍不足则将栏固定在画布安全区底部并显示“图片工具/蒙版工具”，不盖住输入框，不瞬间跑到无关联角落。
- 选中对象完全离开视口时隐藏跟随工具栏，保留可访问的“定位选中对象”。点击工具栏按钮不清掉对象选择；在工具栏与对象间移动指针不关闭工具栏。
- 图下“抠图”在单张有效图片且能力可用时可用；蒙版栏“抠图”只在有效蒙版且无提交在途时可用。两个同名按钮的辅助说明分别为“编辑主体蒙版”“根据当前蒙版生成透明图片”。
- 下载仅对可读的完成资产可用，透明结果建议提供原始 PNG；不把浏览器已发起下载标为文件已存到用户磁盘。画板合成/全画布导出若未实现则不放可点击假入口。
- 执行方案：计划完成、引用有效、能力可用、无冲突执行时可用。重试：确认终态失败且步骤可重试时可用。未知状态只可查询；不以短超时直接解锁重试。
- 灰显按钮必须带能聚焦到的说明或相邻说明，不能只有颜色差异。未验证能力统一标“待接入/待验证”，不出现成功演示。

### 焦点与可访问性

- 工具栏是真实 button；组/对象有名称；状态通过 `aria-live="polite"` 只播报关键变化，不每秒播报加载。图像方向使用“方向 1–4”，抠图结果使用“方向 1 的抠图结果”。
- Tab 依次进入顶栏、左工具、画布可操作对象/组、底部输入和右侧对话。工具栏内部可用方向键切换；大画布提供对象列表或可聚焦对象入口，避免键盘只能操作周边面板。
- 弹层打开后焦点进入其标题/首个操作，关闭回到触发按钮；模态预览约束焦点且背景不可操作。非模态对象工具栏不锁焦点。
- Enter 在底部多行输入中默认换行，Ctrl/Cmd + Enter 发送；若产品最终改为 Enter 发送，必须考虑输入法组合态与 Shift + Enter，并在输入框给出快捷键提示。文本组合过程中不触发发送或全局快捷键。
- Esc 的范围按最内层优先：关闭菜单 → 关闭预览/弹层 → 退出文字/蒙版模式 → 取消选择。Ctrl/Cmd + Z 在文字编辑、蒙版、画布三种作用域互不串用。

## 恢复和撤销的边界默认

1. **画布撤销只撤销文档变更。** 移动、缩放、插入、移除、文字编辑形成可逆操作；撤销已完成生成结果的插入时，资产与任务历史保留，且服务端记录已撤回的落位，刷新不能复活。撤销不把已执行模型调用“倒回去”。
2. **已提交生成与画布保存独立。** 生成请求必须先固定文档归属；后台完成由服务端持久化资产与文档落位，前端关闭也不能丢结果。UI 只有在对象确实持久化进入画布后把整项操作标为完成。
3. **草稿分别持久化。** 对话文本/引用、蒙版草稿可本地备份，画布服务端保存是“已保存”的依据。恢复草稿时显示来源和恢复状态；本地备份不等于全应用离线可用。
4. **保存冲突不能悄悄覆盖。** 多标签页或后台结果写入导致版本变化时，保留当前操作并重新获取最新文档；可安全重放位置/文字等操作后再保存，不能用全量旧快照覆盖新结果。
5. **放弃未保存修改的范围写清。** 仅放弃尚未持久化的名称/布局/文字变更；已经确认提交的生成仍继续；未提交蒙版/对话草稿默认保留，若要删除需单独明示。
6. **能力不可用不扩大到全部编辑。** Agent 离线保留手动工具；某图像服务失效不清空文档；全应用服务离线只承诺已有内存/已缓存内容，不能把未开发的离线产品能力写成已完成。

## 第二轮希望其他角色回答的具体质询

- 产品经理：是否同意部分完成首版采用“保留原组 + 显式重开四图组”，把补缺方向与自由拆组后置？这能避免“首版固定四张”与局部重试的歧义。
- 全栈：是否能在服务端持久化唯一落位记录/撤回状态，并把“任务已结束、资产已生成、对象已加入”分开？否则刷新及撤销验收无法保证。
- UI：长工具栏在 100% 缩放下遇到 4 张横排及底部输入框，能否给出安全区收纳状态，明确绑定哪张图，并保留用户要求的图下栏形态？
- 用户角色：在蒙版退出后提示“草稿已保留”，再次进入恢复，比每次弹弃改确认是否更符合继续创作预期？需要明确这仍是基于假设的走查。
- 所有角色：Agent 若选择“抠主体 → 生四个背景”的首条用例，是否接受蒙版处明确暂停，让用户点“抠图”后再继续已展示的其余步骤？本轮不应通过自动生成绕过该检查点。

## 待验证事项

- 四方向的真实并发提交能力、整组终态定义、可取消程度和异常部分返回信息。
- 蒙版识别与结果生成能否真正分离，源图/蒙版的尺寸映射和透明输出质量；笔刷图形不等于真实可用蒙版。
- Agent 能否按可见引用正确理解图像；在视觉能力未验证前只允许使用指定资产的已知元数据及确定性工具。
- 服务端持久化、重放、去重、撤销与后台完成的竞态处理，以及本地草稿恢复支持。
- 视频已验证范围是文生视频流程；画布视频导入、预览/拖动、源素材关联和图生视频需要分别验收。
