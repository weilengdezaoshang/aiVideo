# 产品经理独立评审 · v0.4 第一轮

日期：2026-09-09。角色：产品经理。本文为方案评审，不代表项目负责人批准，也不表示功能已经实现。

已完整阅读共享背景与角色提示词、[PRD v0.3](../../PRD-创作平台与画布Agent-v0.3.md)，以及[线框 v0.3](../../低保真线框图-创作平台-v0.3.html)的页面结构、状态文字和行为链接。线框为阅读依据，没有将锚点跳转当作真实应用操作，也没有进行模型调用或商业用户访谈。本角色未重新审计代码；代码现状沿用 PRD §6 的陈述，实际可复用程度由全栈角色核对。

## 定位与完成标准

**一句话定位：让开发者本人和首批体验者在可持续保存的无限画布里，通过明确的手动操作与可追踪的 Agent 协作，把想法和原图变成可挑选、可加工、可下载的图像素材。**

这是基于用户已确认“平台方向、首版画布＋Agent、首批本人及体验者”的本轮收敛建议，不替换为未经验证的商业用户画像。

首版完成标准：体验者可以从工作台画布 Tab 创建并命名画布，完成一轮真实的四方向同时生图，选中一图，通过手动路径或 Agent 引用路径准备蒙版，在蒙版栏显式点击“抠图”后得到源图右侧的透明 PNG；下载该素材、返回列表、刷新并重开，原图、方向组、派生关系、位置、对话与任务结果仍一致。至少实测一次部分返回、重复事件、保存失败及刷新恢复。聊天回复成功、静态占位、Mock 演示均不能独立满足此标准。

## 范围清单

### 首版必须做（本轮收敛建议，含既有约束）

1. 三层入口闭环、默认画布 Tab、稳定文档地址、名称/位置/素材/对话保存与可靠返回；满足 W01–W10。
2. 左侧四工具、本地上传与资产导入分开；画板与文字能新增、修改、保存并重开；原生图片与透明 PNG 能显示、选中、移动、按比例缩放和下载。
3. 四方向生成、一个组及四个稳定槽位、真实整组任务、画布/对话相同引用、部分失败的完整说明；满足 W15–W16。
4. 蒙版识别、画笔增补/橡皮删除、局部撤销/重做、显式“抠图”提交、失败保留蒙版、源图右侧插入；满足 W17。“辅助选择”语义未验证前保留不可用说明，不编造工具效果。
5. 一条可完成的 Agent 用例与明确范围：实际引用、准备蒙版、等待用户提交、生成、落位、记录、取消/恢复；每次具体生成操作都可追到原需求、输入资产与蒙版版本。
6. 可理解的生成/文档/Agent 各自状态、重复请求与事件不造成重复产物、任务完成在离开画布后仍归属原画布。
7. 本轮建议的最小视频范围：在现有文生视频能力不回退的前提下保留原有入口；通过资产导入把已验证的视频放入画布，支持海报帧、来源、时长、播放/暂停和原文件下载。此项排在图像核心闭环后，不能为它阻塞图像原型评审。

## 五个关键问题（按严重程度）

### P0-1：Agent 尚无首条完成用例，线框容易把执行边界先行定死

**依据：** PRD §4.2 明确用例、视觉理解、执行范围和恢复均未确定；S16–S18 却画成“把主体抠出来”发送后直接得到结果，未覆盖蒙版确认的暂停点。共享背景要求手动抠图的两阶段步骤不能被绕过。

**建议：** 首版采用下面的用例 A。Agent 把自然语言变成明确工具动作并准备蒙版，进入“等待你确认主体范围”；用户在蒙版栏点击“抠图”后才发起结果生成。计划卡须显示源图缩略图、“只处理这张图”“新增 1 张透明素材”“原图保留”。对于“继续处理下一张/生成背景”等新要求，另建新计划，不静默扩展任务。

**验收：** 发送指令到蒙版就绪期间，透明结果数量保持 0；即使发送“做好了就导出”也不能宣称本地文件已保存。显式提交后只有一张新透明图，用户可定位、下载并继续引用。若所选模型无法读像素，只显示资产名称/引用，不声称理解服饰、主体身份等图像内容。

### P0-2：四方向数量已确认，但差异标准、真实同时执行与重试范围仍不可验收

**依据：** PRD §3.5、W15–W16；线框 S09、S12、S38、D07/D19。文生图验证不覆盖不同提示词四路执行。

**建议：** 需求提交时保存共同约束，系统产出四条短方向说明，说明在哪些构图/场景/光线等维度不同。首版不加四套复杂参数表单，可在对话结果卡展开“本轮方向”。前端可在计划阶段显示“准备四个方向”，只有后端能力检查通过并接收整组任务后，四占位一起显示“生成中”。供应商内部请求可以为四个子调用，但必须真实同时派发或原生批量执行，用户侧始终是一组任务。

**异常范围建议：** 首版部分返回仅提供“查看失败原因”“使用已有结果”“重新生成一组 4 张”；后者显式创建新组且保留旧组。暂不做按失败槽位补图，避免新一轮数量规则与旧组覆盖语义混乱。“重新生成”不得在失败后自动发生。

**验收：** 提交后四槽位同批出现，不逐张排队；整组终态前不把局部结果当成整个任务完成；2 张有效时明确“部分完成 2/4”。重开恢复旧组，点击新一轮才生成新组。四方向质量采用人工样例检查，不编造质量分数或完成比例。

### P0-3：保存成功、模型完成和画布落位是三个结果，现有分期没有把恢复作为完整验收

**依据：** PRD W03/W07/W08/W16 与 §7 阶段 B 只列 W08/W10 不匹配；S05、S25–S30、S33 缺少结果不明及恢复按钮细则。

**建议：** 文档顶栏只表达文档保存状态；任务卡分别表达执行中/结果已生成/正在加入画布/完成/部分完成/需要处理。网络重连和刷新执行查询，不重发生成。已生成但落位失败显示“结果已保留，重新同步画布”，这一步不调用模型。返回列表时有任务不必阻止离开；只有未保存本地修改需要保护。

**验收：** 双击新建只有一个文档；新建响应丢失后可查询同一请求并打开；生成时返回并重开、完成事件重复到达、模型完成后落位失败并重试，均只有同一组对象。保存失败不能出现“已保存”；明确放弃仅放弃未保存文档编辑，不撤销已提交任务、不删除已保存资产。

### P1-4：工作台与视频的示例入口扩大首版范围，却未说明用户从何开始

**依据：** PRD §3.1 的默认 Tab 未定，S01 同时展示快捷生成和画布入口；S31/S32 的表单仍待确认，S22 未定义来源；文生视频已验证但图生视频未验证。

**建议：** 首次打开落在工作台的画布 Tab，空态只突出“新建画布”；仍保留平台壳层。既有图片/视频能力若可工作，则保留可访问入口并标清所在模块；不为占位页面制造可点击的主导航。视频先交付“已生成素材→资产库→选定画布→预览/下载/来源”，图生视频和分镜后续单独验收。新建画布的主路径不要求先生成视频或配置全部模型。

**验收：** 用户不理解模型术语也能创建第一张画布；切换模块不新增文档或生成任务。视频卡片明确“文生视频”、原提示词/生成任务、所属画布；有输入图才展示输入图来源，不能为文生视频编造参考图。

### P1-5：导出、画板和文字均有入口，却没有最小操作合同

**依据：** PRD §3.4、W14，S23/S24/S35/S36、D13/D16/D17；工具栏 D21 仍大量灰显占位。没有下载，用户无法完成“素材可带走”的闭环。

**建议：** 首版只下载单个已生成/上传的原始资产：透明主体为 PNG，普通图片保留存储格式和像素尺寸，视频原文件；頂栏“导出”未选中可下载资产时提示先选中图片或视频。批量/画板合成留后续。画板默认 1024×1024 作为可命名空间框，支持位置/大小保存，首版不裁剪内容、不自动改变对象归属；界面文案明确“用于组织素材，暂不合成导出”。文字采用默认系统字体、黑色 24 px，多行纯文本，支持修改/移动，Esc 退出编辑而不是删除对象；精细排版后续。上述默认均为本轮建议，可由交互角色修正。

**验收：** 选择透明结果下载能获得带透明通道的 PNG；无对象时导出不进入假加载；浏览器发起下载只标“下载已发起”。画板和文字新增后刷新重开仍存在；点击取消本地文件选择、关闭资产面板均不新增对象。未实现的工具在评审原型中标“后续”，不能产生虚构的成功反馈。

## 两条 Agent 用例比较

| 用例 | 用户任务与价值 | 能力依赖 | 验收难度与范围 | 推荐 |
| --- | --- | --- | --- | --- |
| A：引用一张图，协作抠出主体并放在旁边 | 用户用普通话指定动作；Agent 解析范围、准备可修改蒙版、等待用户决定主体边界，再完成透明素材落位。锻炼引用、结构化工具、暂停、任务与文档恢复 | 明确资产引用、蒙版识别与编辑、透明合成、对象新增、持久化；无需宣称视觉语义理解 | 低至中：一个源图、一份提交蒙版、一张派生素材；人工提交点清楚，易于故障注入 | **首版推荐** |
| B：抠出主体，再生成四个方向背景供挑选 | 为下一步创作准备主体及背景候选，更显多步骤价值；不承诺自动合成成图 | A 全部＋四方向规划/生成；若“匹配原图风格”则还需已验证视觉理解或用户描述 | 中至高：双生成阶段、两个独立结果组/派生关系、部分成功、继续执行与调用范围更复杂 | A 与四图单轮均验收后再做 |

A 的价值不在于多放一层聊天按钮，而在于将“你指的是哪张图、处理到哪一步、何时需要你调整、失败保留了什么”做成可追踪且可恢复的交互。若不能完成这些能力，暂不应把普通一键抠图包装为 Agent。

## 推荐用例 A 的完整流程与验收合同

| 步骤 | 用户看到/做什么 | 系统动作与范围 | 可观察验收 | 失败/退出 |
| --- | --- | --- | --- | --- |
| A01 引用 | 选图→“添加到对话”；底部出现可移除的缩略图与名称 | 绑定当前画布的 assetId、objectId 与版本；本轮只接受一个引用 | 切换画布不能引用到另一画布的残留选择；移除引用不删除素材 | 无引用说“这张图”时要求先选一张，不猜最近图片 |
| A02 说明目标 | 输入“把这张图的主体抠出来，放旁边”并发送 | Agent 验证引用可读及工具能力；形成只处理该图的计划 | 对话保留原消息、真实引用与“准备主体蒙版→由你确认→新增透明素材” | 超范围/能力不可用时保留输入与引用，不伪造完成 |
| A03 准备蒙版 | 原图蒙版识别状态、右下“抠图”禁用 | 只发起蒙版准备；不创建透明结果 | 识别完成才出现可编辑覆盖区；背景仍可见 | 识别失败保留原图，允许重试识别或返回图片 |

| A05 显式生成 | 用户点击蒙版栏“抠图”，按钮“生成中…” | 冻结这次引用和蒙版版本；提交一个透明结果任务；锁定重复提交 | 双击只有一次任务；任务期间不能修改已提交蒙版；不自动加四方向背景 | 失败保留原图与蒙版；“返回蒙版”不重试，用户再次点击才提交新尝试 |
| A06 落位 | 源图右侧新增透明图并选中；对话缩略图可定位 | 一个派生资产＋一个画布对象；来源指向源资产和蒙版；组内后续顺延 | 原图在原位置；四方向槽位关联仍只有四个；重复事件不新增第二张 | 落位失败时“结果已保留，重新同步画布”，不重新生成 |
| A07 继续 | 可下载、引用结果继续描述或返回画布列表 | 操作完成条件是结果已持久化且已归属画布 | 重开同一文档可看到原图、透明结果、来源、原会话；定位指向同一对象 | 刷新恢复查询现有执行；暂停中的任务显示“待继续”，不自动重做工具 |

## 交付依赖与讨论问题

实施顺序建议：能力验证及系统对象约定 → 文档导航/保存恢复 → 画布对象与素材 → 四图组与手动蒙版闭环 → Agent 用例 A → 视频资产联通 → 用例 B 与其他深化。阶段验收必须明确覆盖 W11–W17，不能沿用 PRD §7 简略表把这些新增要求遗漏。

向全栈质询：现有抠图产物能否分离出可编辑的源尺寸蒙版？如果仅有透明结果，补齐识别与合成各需哪一条可验证路径？四图是批量还是四路并发，何处能够阻止不满足能力时提交？

向用户/交互质询：推荐用例 A 增加“Agent 等待你确认主体范围”后，用户能否区分它与普通抠图以及普通聊天？蒙版退出保留草稿是否足够直观？

向 UI 质询：S15 五张及后续派生素材仍处于共同容器时，怎样让用户区分“4 个候选方向”和“新增透明素材”，而不把派生图误作第 5 个方向？
