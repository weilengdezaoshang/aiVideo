# 用户角色 · 独立评审

日期：2026-09-09。评审材料：五角色提示词共享背景与③用户角色要求、v0.3 PRD全文、v0.3低保真HTML的全部43个状态。未阅读其他角色报告或v0.4 PRD后形成此稿。

**证据范围：这是基于假设的首次体验者视角走查，不是真实访谈。** 我读取了文档与HTML结构、文本、链接去向，没有在浏览器中亲自操作。因此以下“第一眼”“页面实际表达”均为文档推测，不是点击成功、视觉可用性或真实生成能力的实测结论。

角色假设：我会描述想要的画面并上传素材，不懂模型、任务队列、工具调用；我想获得一组候选图，把喜欢的一张抠出主体，保留原图，并能回来继续。

## 1. 从工作台找到画布，新建并命名

- **我想做什么：** 开一个能保存图片和操作记录的地方，命名为“咖啡店素材练习”。
- **第一眼会点击：** S01的“进入我的画布”或左侧“画布”，在S03点击“新建画布”，进入S06后点击“未命名画布 / 重命名”。
- **我预期：** 创建一份内容，打开后能直接输入；改名后下次能找到。
- **文档实际表达：** S02先读列表，S04创建后才进入，S07给出命名与保存入口；S25在保存成功后显示已保存。PRD W01–W07已覆盖基本路径。
- **我犹豫的地方：** S01的大输入框比画布入口更突出，我可能先在首页输入，随后不确定图片会保存到哪里；S06“返回工作台”实际回“我的画布”，名称不完全一致。S05遇到“暂未确认创建结果”后没有确定可操作的下一步。
- **最小帮助〔本轮建议〕：** 保留确认的画布路径，让画布入口说明“创建并保存一次持续创作”；返回按钮写“返回我的画布”。结果不明时给“查询创建结果”，并说明“查询不会再创建一份”。

## 2. 描述创意，理解四张图片和完成状态

- **我想做什么：** 输入“一只像人一样跳舞的橘猫”，拿到可比较的创意候选。
- **第一眼会点击：** S09底部输入框与“发送”；完成后查看S13横排的四张图。
- **我预期：** 一次拿到四种构图或氛围，从中选一张；四张属于刚才同一次描述。
- **文档实际表达：** S09写明“4个方向 × 每方向1张”；S12四个位置同时显示生成中，没有百分比；S13同标题容器和右侧同组预览显示4/4，S38明确2/4部分完成。
- **我犹豫的地方：** “方向”还是抽象词，只有图片1–4，无法提前知道差别落在哪；S38让我去看待确认清单，不能继续获得候选。若以后按钮叫“重试”，我会猜它只补缺失的两张。
- **最小帮助〔本轮建议〕：** 提交前说“同一需求，探索4种构图、光线或风格”；完成后每张有一句区别说明。部分失败保留现有图片，若首版只能整轮再做，按钮直写“另生成一组4张”，同时写明“本组保留，生成内容可能不同”。

## 3. 选一张，调整蒙版并生成透明图片

- **我想做什么：** 去掉背景，保留猫和尾巴。
- **第一眼会点击：** S39的单张图片，下方“抠图”；在S14按蒙版栏的“抠图”。
- **我预期：** 第一次点击后可以检查保留范围，确认后才得到透明图片。
- **文档实际表达：** S40识别、S14蒙版编辑、S42结果生成分开；S14出现蒙版本身不新增图，只有蒙版栏“抠图”才生成，符合已确认约束。
- **我犹豫的地方：** 两次都叫“抠图”，第一次可能被理解为已执行；“蒙版”不告诉我涂过的地方是留下还是删除。S14说明画笔、橡皮和退出的细节仍待确定，我担心调整尾巴后点空白会丢失工作。
- **最小帮助〔本轮建议〕：** 不改已确认的最终按钮名“抠图”；进入后展示“1. 检查保留区域”，生成前写“高亮区域将保留；点击下方‘抠图’生成透明图片”。画笔/橡皮的提示分别写“增加保留区域”“减少保留区域”。离开有修改的选区时保留草稿并明确退出结果。

## 4. 找到结果并确认原图还在

- **我想做什么：** 对照原图检查效果，决定是否继续使用。
- **第一眼会点击：** S15原图右边的新增对象，或右侧“定位画布结果”。
- **我预期：** 原图不被覆盖，透明版挨着它；失败也不损坏原图。
- **文档实际表达：** S15排列为原图1 → 抠图结果 → 图片2 → 图片3 → 图片4；新图选中、棋盘格背景和来源说明存在；原文生图仍为4张，抠图结果是新增的派生素材。
- **我犹豫的地方：** 结果长在组里后实际看到五张，但标题仍4/4，需要注意“新增1张抠图结果”才能明白。S15没有定义重复做第二次后哪张最新；我可能把透明棋盘格当成图片自身背景。
- **最小帮助〔本轮建议〕：** 源图与结果保持“图片1”“图片1·抠图1”名称关联；新增结果说明“透明背景（棋盘格仅用于预览）”；标题保持“4张创意图 + 1张抠图结果”。重复处理采用明确编号并保留全部原有对象。

## 5. 把单图加入对话，让Agent理解“这张图”

- **我想做什么：** 告诉助手“把这张图主体抠出来，放在旁边”，避免操作错误对象。
- **第一眼会点击：** 图片下方“添加到对话”，检查底部“引用素材：人物原图”后发送。
- **我预期：** 助手说明它要处理哪张图片、会留下什么，然后带我确认主体范围。
- **文档实际表达：** S16有文字引用，S17示例直接开始“读取指定素材 → 处理主体 → 放入画布”，S18已经有结果；执行前确认和自动边界仍待确定。PRD §3.4的手动抠图有显式确认，但S16–S18没有把蒙版确认表现出来。
- **我犹豫的地方：** 我可能以为发送就自动生成，也可能不知道为什么手动需要检查而对话不需要。我在发送前换选另一张图时，不清楚“这张图”跟随选中还是保留原引用。单次抠图本来两步就能完成，若对话只是加很多确认，我不一定愿意用。
- **最小帮助〔本轮建议〕：** 引用显示缩略图、名称和删除入口；发送后的引用固定，不悄悄跟随选择变化。对话先说明“针对这张图准备保留区域；你检查后点击蒙版栏‘抠图’，结果放在原图右侧”，给进入该步骤的按钮。首条Agent用例的价值应限定为“明确目标、带我走完并找回结果”，是否值得长期使用仍待体验验证。

## 6. 失败、保存失败或刷新后继续

- **我想做什么：** 知道之前的工作是否还在，并能继续，不意外生成重复图片。
- **第一眼会点击：** S26“重试保存”；S28等待查询恢复；S41“返回蒙版”；S33/S38寻找继续入口。
- **我预期：** 再次打开看见同一画布、图片、对话与我调整的范围。点击恢复不会再生成一轮。
- **文档实际表达：** 保存失败不假报成功；恢复查询旧任务不重发；抠图生成失败保留蒙版；结果不明与明确失败已区分。但S05、S19、S33、S38的恢复动作仍待确认，刷新后的蒙版草稿保护尚不明确。
- **我犹豫的地方：** “失败”与“尚未查到结果”容易混淆；没有可用按钮时，我会刷新或重发原话。S26“明确放弃未保存修改”没说明会丢哪些东西，我不敢离开。若我先前保存过，顶栏“已保存”不能说明刚编辑的蒙版也已保存。
- **最小帮助〔本轮建议〕：** 不确定时只给“查询结果”，显示“尚未确认，请勿重新发送”；明确失败才给对应的新生成入口。保留输入、已成功图片和选区草稿；放弃前说清影响范围，保存状态至少区分画布与当前选区草稿。查询无结果也允许返回列表继续其他工作。

## 7. 查看视频，理解来源和画布归属

- **我想做什么：** 播放视频，确认它来自哪段描述或哪张图片，并知道以后从哪里找。
- **第一眼会点击：** S32的视频结果播放位置，或画布中视频对象的播放入口，进入S22。
- **我预期：** 点播放就播放，点外边框选中，拖边框移动；预览里显示名称、来源、所属画布。
- **文档实际表达：** S22有播放区域和返回入口，但播放方式、来源和进入方式都待确认；S32说明文生视频已验证，图生视频需单独验收，没有可用首帧入口。
- **我犹豫的地方：** S32生成的视频如何进画布没有完整路径；“素材已位于画布”跳过了我的实际操作。带图片引用时若只做文生视频，我可能错误地认为图片真的参与了生成。
- **最小帮助〔本轮建议〕：** 首版优先给已有视频“导入资产 → 加入当前画布 → 明确播放按钮 → 弹层预览”的闭环。预览显示“来自文字描述/本地上传”等真实来源和当前画布名；没有输入图就明确“未使用参考图片”。图生视频入口继续待验证，不借视频预览暗示已具备。

## 最影响完成任务的五个问题

1. **关键：Agent示例跳过我检查保留区域的步骤。** S16–S18与S40→S14→S42应接成同一条可理解流程；发送不应被误解为蒙版已确认。
2. **关键：失败与结果未知后的下一步没有落定。** S05/S19/S33/S38必须给出可继续的真实动作，区分只查询、回选区编辑、另做一组。
3. **高：两次“抠图”和选区工具含义不清。** S39/S14保留确定按钮名，补“进入检查”与“实际生成”的状态说明、保留区域语义和草稿保护。
4. **高：四张方向、派生图和重做范围不易预测。** S09/S13/S15/S38需要方向说明、来源名称及“另生成一组4张”的准确按钮，避免误以为补两张或第五方向。
5. **高：视频播放有状态，没有来源到画布的完整路。** S22/S32先完成已有视频导入与预览、真实来源和所属画布的可见关联。

以上是用户角色的本轮建议，不代表项目负责人批准，也不代表真实访谈发现或产品已经实现。
