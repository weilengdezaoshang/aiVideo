# PRD:生成式创作画布(GenCanvas)

> 版本 v0.1 · 2026-09 · 状态:草案,待评审
> 本文档基于 2026-09 多轮产品讨论收敛,前身项目为 SwarmUI 风格生成工具(aiVideo 仓库)。

---

## 1. 背景与问题

### 1.1 现状
仓库现有能力:文生图 / 图生图 / 局部重绘 / 图生视频,Provider 抽象(Mock + ComfyUI),FIFO 队列 + SSE 实时进度,历史持久化。**核心缺口:结果以网格列表呈现,生成是"提交后等待的请求",创作过程不留痕、不可延续。**

### 1.2 机会
- 无限画布已是 2026 年 AI 创作工具的主流形态(Krea、Lovart、Flora、即梦、LiblibAI 均已布局),方向被头部产品真金白银验证;
- 但国际竞品全部是闭源 SaaS,开源侧只有玩具级项目——**"生产级、可自部署、BYOK 的开源画布"这个位置目前是空的**;
- ComfyUI 用户基数巨大但节点图门槛极高,缺少一个友好的画布外壳。

### 1.3 核心产品判断
1. **"AI 一次生成到位"不存在**——全行业现状,不是可修复的缺陷。产品价值 = 把用户从"不满意"迭代到"满意"的路径做到最短(裁缝店逻辑:不解决衣服不合身,解决改起来容易);
2. **技术深度押在工程侧**(画布引擎、状态同步、管线),模型是可插拔的商品——Provider 抽象已在仓库中存在;
3. 模型做不了的(如 SVG 矢量)用确定性管线补,**不在模型主场与模型硬碰**。

## 2. 产品定位

> **一句话:ComfyUI 与多家模型 API 的开源创作画布——自部署、BYOK、中文友好。**

| 维度 | 决策 |
| --- | --- |
| 目标用户 | 首要:被 ComfyUI/WebUI 门槛劝退的 AI 创作爱好者;次要:需要私有化部署的创作团队/企业(远期) |
| 差异化 | ① 开源自部署(竞品全闭源 SaaS)② ComfyUI 原生集成 ③ 创作过程留在画布上(空间谱系) |
| 竞品 | Krea / Lovart / Flora / 即梦 / LiblibAI(均为 SaaS);开源侧无生产级对标 |
| 名称 | GenCanvas 为工作代号,【待定】 |

**对"提示词广场"原始想法的处理**:v1 不做任何广场/社区。提示词以"收藏复用"形式存在于个人画布中;数据模型(谱系 + 参数)按"未来可同步到中央广场"设计,中央广场留给商业/托管阶段。

## 3. 目标与非目标

### 3.1 v1 目标(内部可用 → 开源 Beta)
单人可完成的最小完整产品:一张画布上完成 生成 → 变体 → 局部重绘 → 图生视频 → 导出 的完整创作闭环,自部署零门槛。

### 3.2 v1 明确不做(Non-goals)
- 多用户 / 账号体系 / 积分 / 支付(商业阶段)
- 广场、社交、协作、多标签页文档同步(v1 单标签页,见 §9)
- 对象内版本树、谱系连线可视化、小地图、模板库
- AI 直接生成 SVG(仅做位图→矢量导出,见 §5.6)
- 移动端适配
- 旧网格视图的完整迁移(保留为素材库入口)

## 5. 用户旅程与交互规格

### 5.1 整体画面
全屏无限画布(灰底网点),创作对象散布其上。顶栏:画布切换 / 模型选择 / 进行中任务数 / 保存状态。悬浮提示词面板(可收起)。右下角缩放控件。

### 5.2 基础手势
- 平移:触控板双指 / 空格+拖 / 鼠标中键;缩放:滚轮 / 捏合(以光标为中心);
- 单击选中、拖框多选、拖动移动、Delete 删除;框选需支持对象 bounds 求交。

### 5.3 五条核心流程(P0)

**① 文生图**:Tab 呼出提示词面板 → 输入 → 生成 → 面板收起,画布中心出现转圈占位框 → 完成后占位框变真图。**等待期间画布不被锁死**,可继续发新任务(并发占位框并存)。

**② 以图生图(变体)**:右键图 →"以此为参考生成" → 面板自动挂参考图 → 新图落在源图右侧第一个空白位(螺旋探测),源图不动。连续操作形成空间变体群 = "空间谱系"。

**③ 局部重绘**:双击图进入重绘模式(其余对象变暗)→ 笔刷涂抹(可调笔径/擦除)→ 输入区域提示词 → 生成 → **结果为新对象,不覆盖原图**。

**④ 图生视频**:右键图 →"生成视频" → 时长等参数 → 占位框(耗时长)→ 完成后画布内视频对象,点击播放。

**⑤ 关闭再打开**:画布自动保存(防抖 2s + beforeunload 冲刷);进行中的任务占位框跨会话保留——刷新后仍在原地转圈或已完成落位。

### 5.4 占位框交互(P0)
转圈 + 进度百分比;悬浮显示"取消";**生成中可拖动**(结果落位由用户控制);失败变红色错误卡(原因 + 重试,重试=谱系参数原样重发);删除占位框 = 级联取消任务。

### 5.5 迭代辅助手段(P1/P2)
| 手段 | 优先级 | 说明 |
| --- | --- | --- |
| 变体批生成 | P1 | 一次 4 张平铺选取(实现为 4 个独立任务,见 §8.4) |
| 草稿模式 | P2 | 低步数/小尺寸先出小样,满意后原参数高配重出 |
| 种子锁定 | P2 | 锁构图换细节 |
| 提示词收藏 | P2 | 收藏/复用/历史搜索(复用现有能力) |
| 素材库 | P1 | 旧网格历史视图保留,素材可拖入画布 |

### 5.6 SVG 导出(P1)
右键图 →"转矢量" → 调参面板(左原图/右实时预览,滑块:颜色层数/细节/简化)→ 导出。实现:vtracer WASM 浏览器端执行(零服务器成本),超大图降级服务端 CLI。**界面向用户明示适用范围**:logo/图标/扁平插画效果好,照片不适用。不做 AI 生成 SVG。

## 7. 信息架构与数据模型

### 7.1 对象模型(客户端文档 JSON)
```
CanvasDoc { id, objects: Map<id, Obj>, order: [id] }
Obj(图像/视频/占位/错误卡) {
  id, kind, x, y, width, height,
  assetId?,                    // 指向资源 blob,文档只存引用
  lineage? { fromId, params }, // 谱系:每个生成结果=新对象
  gen? { jobId }               // 仅占位对象携带
}
```
### 7.2 双 Store 分离(架构核心决定)
- **DocStore(可撤销)**:对象/变换/谱系,只由用户命令驱动,入 undo 栈;
- **TransientStore(不可撤销)**:相机、选中、生成进度——SSE 事件驱动,绝不进 undo 栈。

### 7.3 存储布局
`data/documents/`(文档 JSON)+ `data/assets/`(原图 + 多级缩略图 256/1024,生成完成时同步产出)。与现有 `data/` 结构兼容演进。

## 8. 技术方案概要

### 8.1 选型(已核实)
- **画布引擎:Konva**(MIT,14.7k star,CDN UMD 零构建可引入,Node 端可渲染→服务端缩略图/导出复用同一场景图);备选 LeaferJS;tldraw 排除(自定义许可证 + React 绑定 + 不接受贡献);
- **工程化**:零构建起步(原生 ES Modules + JSDoc + `tsc --checkJs`);前端代码超 ~3k 行后升级 esbuild watch(产物仍为纯静态文件);不上 Vite;
- **SVG**:vtracer(MIT,官方 npm WASM 包 + Rust CLI)。

### 8.2 异步生成 × 画布状态(核心自研层)
- 生成任务**绑定对象 id,不绑坐标**;占位对象携带 jobId,SSE 事件(job/image/snapshot)驱动状态迁移;
- 事件处理为**纯函数 reducer**(可 node:test 单测),语义:**未知 jobId 一律安全丢弃**(防全局广播/事件先于 POST 响应到达);
- **对账**:SSE 重连成功与页面加载时,拉 `/api/jobs?all=1` 比对本地占位;服务重启丢任务时查历史兜底,再不行标失败"任务丢失";
- 落位:源对象位置 + 螺旋探测找空位(纯函数,可测)。

### 8.3 撤销/重做
Command 模式;**SSE 创建的对象不进 undo 栈**(避免"撤销移动却删了生成结果"的反直觉);占位创建与 jobId 回填合并为单条命令;滑杆连续变更合并为一步。

### 8.4 后端改动清单(诚实版,非"零改动")
1. 文档 CRUD 端点 + `data/assets/` 存储与缩略图管线;
2. 二进制上传端点(替换 base64 data URL,画布大图/蒙版上传);
3. `GET /api/jobs/:id` 支持查询历史任务(reconcile 依赖);
4. `POST /api/generate` 可选 `clientRef` 透传字段;
5. 【开工前置验证】确认 job-manager 的任务历史在服务重启后是否存续——不存续则 reconcile 需调整策略;
6. 画布提交强制 batchCount=1(多张 = 多任务,规避一对多映射与队列上限问题)。
