01系统全景：前后端统一使用持久化执行架构

所有应用入口共用 PostgreSQL / RabbitMQ / Redis / Celery。开发热重载与容器部署只改变进程启动方式，不切换队列或存储实现。

打开 SVG 大图 ↗下载 SVG下载 Mermaid 源码

单一业务运行架构backend.app 与 backend.production 导入同一工厂。npm dev/start、python -m backend 和默认 Compose 均使用数据库 API，AIVERO_API_MODE 已退役。

开发依旧可以热重载--reload 只影响源码监听；仍需要数据库、Redis、独立 Worker、共享媒体、OIDC 与 HTTPS 配置。缺配置会失败，不回退 JSON 或 Mock 应用。

历史代码的保留范围旧 HTTP/FIFO 仅被隔离评测、性能夹具与兼容测试显式导入，无法用默认无参数工厂启动，禁止操作仓库 data。已有数据需离线导入。

当前功能边界Agent、完整分镜编排、评测 HTTP 页面尚未迁入统一入口；新画布中的部分工作流也未接通。统一入口不代表这些外围能力已经迁移完成。

02前端模块分层：入口、交互核心、文档与网络

当前画布以 canvas-next/app.tsx 为组合入口。React 管工具和面板，CanvasView 管交互与短期快照，DocStore 管持久文档，React-Konva 只承接渲染和输入适配。

打开 SVG 大图 ↗下载 SVG下载 Mermaid 源码

交互与绘制分离Konva 输入先变成显式 CanvasInputEvent。交互层产生预览或命令；拖动中更新短期快照，提交时才进入文档历史，避免每次鼠标移动都成为撤销项。

三类状态DocStore 保存文档；CanvasViewSnapshot 保存相机、选中、工具和笔画；GenerationRuntimeStore 保存请求与进度。它们的生命周期和保存策略不同。

网络栈现状普通页面用 fetch 与类型化封装，landing/workspace/canvas-next 安装同源写请求 CSRF 包装。TanStack Query 主要用于独立评测页；不是全站统一 Query 或 Axios 层。评测源码仍保留，但应用入口不提供 /evals 或评测 API。

当前接线缺口NodeGeneration、Agent、完整分镜及时间线导出模块保留在 canvas/flows，但当前入口没有装配；不能将其全部视为新版界面已实现能力。

03前端状态流：生成实体、画布位置与保存分离

生成实体保留任务身份和结果，placement 决定它是否出现在画布上。SSE 或轮询只合并状态；自动保存只响应需要持久化的文档变更。

打开 SVG 大图 ↗下载 SVG下载 Mermaid 源码

为什么撤销不会重复计费用户历史记录 placement 命令，生成结果更新不进入撤销栈。撤销不自动取消上游任务；只有显式 cancel 才调用删除任务 API。

两种版本不能混用实体 operationId/version 用于前端操作归属与补丁次序；Job 的 stateVersion/progressSeq 用于 HTTP、SSE 和快照的状态合并。

幂等接线的现状CanvasCoordinator 当前只带 clientRef，不带稳定 requestId/documentId。后端可受理，但 clientRef 本身不是幂等键。工作台 CreationIntent 才沿用稳定请求 ID。

保存恢复的范围AutoSaver 已有草稿与冲突保护；resolveDraftOnOpen 和重复标签页保护模块尚未被新入口装配。进度 RuntimeStore 也尚未作为参数传入当前 selector。

04统一后端：事务受理、阶段执行与通知闭环

PostgreSQL 保存任务和执行所有权；RabbitMQ 传递至少一次消息；Celery 每次执行一个阶段；Redis 协調通知、限流和熔断。API 受理不直接调用付费生成。

打开 SVG 大图 ↗下载 SVG下载 Mermaid 源码

四个 daemon 各司其职dispatcher 保证数据库事件送达 MQ；bridge 转成 Celery 执行任务；scheduler 扫描到期任务并恢复租约；notify 将状态变更转成 Redis 唤醒。Compose 不运行 Celery beat。

消息可重复，提交不可盲重试至少一次消息由数据库 claim、lease_owner、execution_epoch 和期限检查吸收重复。Attempt 记录提交尝试；不能确定上游是否收单时转 unknown，不自动重新付费生成。

模型并发与 Worker 并发分开PG 模型槽位代表实际上游任务并发；轮询等待不占 Celery 执行槽。Redis 负责速率和熔断；PostgreSQL 才是任务状态依据，Celery 未使用结果后端。

资源恢复与事件恢复文件先原子落盘并写 receipt，再登记资产；崩溃后可恢复已有产物。SSE 依赖 PG 快照和周期对账，Redis 是唤醒信号，不是事件历史或 Last-Event-ID 重放日志。

抠图仍在 API当前 API 的 rembg 识别仍是 API 进程内单推理线程，Redis 传递跨实例取消标记；只有时间线导出进入 exports Worker。识别结果不持久化为蒙版资产。

05一次生成请求的跨层时序

以下展示统一后端的主路径。任务状态与派发事件同事务落库，执行分成可恢复的阶段，最终经通知唤醒与数据库投影回到浏览器。

打开 SVG 大图 ↗下载 SVG下载 Mermaid 源码

202 的含义请求已被可靠受理，尚未生成完成。结果通过 Job.images、历史与 SSE 异步返回；不能把 202 当成媒体已生成。

图中的合并泳道SVG 将 Dispatcher/MQ、Bridge/Worker 和 Provider/媒体卷合并以便阅读；Mermaid 源码保留更细的独立参与者，模块边界见上一图。

同步与异步 Provider有些图像调用同步返回产物；云视频与 ComfyUI 常经历上游句柄轮询。图中阶段是协议概览，不代表所有适配器都经过完全相同的分支。

失败和取消有句柄就对账原任务；缺句柄且提交不确定时保留 unknown。取消标记不代表上游确认停止；已有完整 receipt 可恢复登记，避免重新生成。

08 当前接口与迁移边界

生成 /api/generate；/api/generate/groupJob + GenerationRequest + Outbox 事务；requestId → Idempotency-Key → 服务端 UUID 回退。缺稳定 ID 时仅 clientRef 不幂等。CanvasCoordinator 当前仅带 clientRef；工作台 CreationIntent 带稳定 requestId。clientRef 本身不提供重放幂等。
