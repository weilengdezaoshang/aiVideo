# Agent 实施提示词：FRAYUNE 完整评测体系

以下内容可以直接作为编码 Agent 的任务提示词。配套技术文档为同目录的 `技术方案-完整评测体系-v1.0.md`。本文要求实施代码，不创建额外任务、不自动部署线上服务或发起付费模型调用。

---

你是本项目的实施工程师。请在 aiVideo 仓库中，根据 `docs/技术方案-完整评测体系-v1.0.md`，实现 FRAYUNE 的评测体系，完成代码、页面、测试、运行说明与验收记录。

先完整阅读仓库 `AGENTS.md` 和技术文档，再核对实际代码。文档的“现有实现”是编写时快照，不能代替当前代码检查。发现差异时，记录事实并调整实现，不覆盖其他任务的修改。

## 一、目标与范围

交付能够实际操作的闭环：

中文用例库 → 创建评测 → Mock / 严格回放 / 受预算约束的真实运行 → 自动评分 → 报告与步骤追踪 → 人工审核 → 问题进入回归集 → 修复后比较 → 发布判定。

必须实现本地可运行的核心系统、中文管理页面、CLI/API、第三方适配及配置说明。不能只交付方案、空目录、接口占位、静态设计图，或使用硬编码结果冒充运行数据。

按技术文档 P0—P4 连续推进，不在完成第一个阶段后就停止。P5 中实现必要的监控、保留、备份恢复和导出能力；事务数据库迁移与持续线上运营依照文档的实际触发条件处理，不为了阶段齐全而提前迁移主应用存储。

依赖真实账户、人工判断、云端权限或付费运行的部分，先完成代码、契约测试和配置入口，明确标记“待真实验收”。继续推进不依赖这些条件的工作，不伪造已验证的生成质量、账单或外部集成。

## 二、开始工作

1. 查看工作区状态、现有分支与适用的 AGENTS.md。保留未提交修改，不执行破坏性清理、重置或整目录覆盖。
2. 阅读 `scripts/eval.py`、`evals/`、`apps/api/backend/traces.py`、`apps/api/backend/app.py`、`apps/api/backend/jobs.py`、`apps/api/backend/providers/`、存储实现以及相关测试和前端构建入口。
3. 根据文档第 20、21 节建立实施清单，保存到 `docs/评测体系实施记录.md`，将需求映射到模块和验收项。
4. 简要说明差距与实施顺序，随即开始修改代码。普通可逆的实现选择自行决定，不为每一步重复请求确认。

## 三、实施顺序

### P0：数据和评测核心

实现版本化用例、不可变数据集快照、Run/Trial/Attempt、步骤事件、素材哈希、结构化评分、报告和旧数据导入。保留现有 `run/judge/report` 兼容入口。

先打通一条真实业务链路上的离线用例，再扩展批次。评分改成类型化规则，修复否定句被子串匹配误判的问题。执行失败、质量失败、裁判错误、未定、未执行分别保存和统计。

### P1：严格录制回放与费用控制

在可注入的 HTTP transport / 领域边界录制请求、响应、错误、轮询、媒体和调用关系。执行回放时继续运行被测业务代码；不能直接返回整条历史测试结论。

实现请求内容与素材哈希匹配、交互消费检查、可控时钟、完整性校验、外网阻断和差异报告。未知请求直接失败，禁止自动转为真实调用。明确 Provider 边界和 HTTP 边界分别覆盖哪些代码。

实现单写者预算账本、原子预留、结算、重试计费、并发争用保护、取消和未知上游状态恢复。真实请求必须经过统一预算入口。

### P2：步骤追踪与人工审核

从 API 入口开始追踪校验、翻译、排队、Provider、下载、保存等步骤，关联 requestId/jobId/traceId/externalTaskId，覆盖异步队列和重启恢复。

实现审核任务、领取租约、独立意见、争议、追加式裁决、错误分类、问题转用例，以及人工标注集上的裁判校准。自动判断和人工判断不互相覆盖。

### P3：中文页面、比较与门禁

按文档第 15 节实现页面与 API，复用项目 React + TypeScript 技术栈和设计体系。至少打通用例管理、新建/运行评测、结果详情、步骤差异、人工审核、录制回放、成本和发布判定。

列表、筛选、按钮、状态、计数、素材预览都连接实际后端。明确展示空态、待审核、证据缺失、预算耗尽和错误。查看历史、离线回放、真实复测、重新评分使用不同操作。

实现分组比较、有效配对、样本量和不确定性说明，以及 pass/block/inconclusive 门禁。不能只展示总体平均分。

为 Promptfoo 提供读取本项目结果的适配；为 Langfuse/OpenTelemetry 提供追踪导出和关联。第三方不可用时仍能本地查看核心证据。避免外部工具再次调用模型判分或重复记账。

### P4：质量能力、校准与压缩实验

为当前 Provider 已支持的图像、编辑、视频任务接入对应输入和评估器。未支持能力明确返回 unsupported；不要写一个恒定分数的函数冒充实现。

实现评分器注册、媒体预处理版本、检查项依赖、评分缓存、裁判校准报告。压缩与多问题合并是可配置实验因素，保存原始输入及处理版本，比较质量和总成本。

测试夹具标明 synthetic/recorded/real 来源。无真实媒体或模型验收时，仅声明契约与流程通过，不能宣称已完成真实图像/视频能力验收。

## 四、不可突破的约束

- 新增前端业务代码全部使用 TypeScript，禁止使用 any 规避类型。纳入现有 typecheck、lint、build 和测试。
- 复用 `app → jobs → provider → storage` 业务链路，不复制另一套生成逻辑。现有 API/SSE 和 data 格式变化必须有兼容测试。
- 主应用保持单进程 JSON 存储。隔离评测数据目录，禁止评测写入真实用户画布、任务或素材。
- 不改变抠图识别的取消、迟到结果防护与线程槽位语义；不缓存或恢复生产 mask、选区和笔画草稿。
- Mock/stub 不用于质量成绩；缓存/回放不算独立真实试验；固定 seed 不等于云端输出完全相同。
- 回放不能访问远程翻译、裁判、模型发现、媒体下载或遥测；所有潜在出口都要纳入禁网测试。
- 不自动使用环境中已有密钥调用真实模型，不发起付费生成、付费裁判、公开部署、真实通知或周期任务。这些需要另行明确授权。
- 默认真实预算为 0；未知用量和费用保持 null。请求已发出但结果不明时，不盲目重试或释放费用预留。
- 评分缓存键包括素材、预处理、检查项、规则、模型修订和语义相关配置。普通缓存不能当作完整录制包。
- 旧运行与原始证据保持可追溯，重跑/重新评分/审核修订均创建新版本。
- 核心证据库为权威数据；Promptfoo/Langfuse 是适配与展示入口，不能成为重复执行器。
- 第三方依赖核对官方文档、锁定验证过的版本；开发依赖准备与回放运行分开，不在断网测试里自动安装或下载。

## 五、验证要求

按文档第 21 节逐条映射到测试或验收记录，尤其验证：

1. 用例冻结后修改源文件，不影响旧 run。
2. 严格断网回放两次业务投影一致，新增外部调用为 0。
3. 改提示词、参数或参考图后回放明确失败，并显示正确差异。
4. 两个并发调用不能花同一份余额；崩溃恢复不能盲目重复付费请求。
5. 失败、未评、未审核和未知费用不被隐藏，不导致通过率虚高。
6. 人工冲突和修订保留完整历史，旧报告不被改写。
7. 修改裁判规则或媒体预处理使缓存失效。
8. 队列异步、取消、恢复和第三方观测故障的行为正确。
9. 页面通过实际操作验证，不能只证明能够编译。
10. 现有测试与 `npm run verify` 通过；不通过时区分本次引入的问题和已有问题，记录证据，修复本次引入的问题。

使用本地模拟服务和明确标记的夹具测试计费、网络故障与外部集成，不需要真实付费调用。测试应覆盖行为和失败边界，不能只是重复实现内部逻辑。

## 六、推进与交付

持续更新实施记录：完成模块、验证命令与结果、关键设计偏差、外部依赖、尚未验证的范围。长任务上下文切换后从记录继续，不重新实现已经完成的部分。

实际实现与技术文档有合理差异时，说明原因并同步更新文档；不通过删掉困难的验收项来宣布完成。不自动提交或推送 Git，除非另有明确要求。

最终交付：

- 可运行的代码与中文页面。
- 使用实际存在的命令编写的启动、评测、回放、审核和比较说明。
- 不含凭据的配置示例、依赖锁定和外部集成步骤。
- 测试结果、离线演示证据、旧数据兼容说明。
- 实施记录：明确区分已实现、已验证、待人工/真实服务验收、条件触发后再做的事项。

验收完成标准是：用户能在本地用一条用例完成执行、看结果、查步骤、人工审核、严格回放、修复后比较和生成门禁结论；批量能力与文档要求有对应测试。外部真实质量未验证时必须如实标明，不能把离线通过描述为生产验收完成。
