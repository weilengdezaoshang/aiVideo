# 草稿与确认交互 · v4

本轮为产品设计稿，不修改应用代码。沿用 v3 的白色顶栏、浅灰点阵无限画布、左工具栏、右侧文档对话，以及「雨后漫步」素材。目标是让人先看画面再决定，并清楚知道哪个版本正在等待、下一次动作是否生成或花费。

## 范围与视觉

- 桌面逻辑视口 1600×1000，生成目标 16:10；实际图片尺寸以生成记录为准，不拉伸输出。
- 画布约占 72%，右侧对话约 28%。主图下方形成紧凑的确认带；聊天使用低对比度状态卡，减少重复大缩略图。
- 白色 #FFFFFF、画布 #F7F8FA、正文 #24262B、次级文字 #737987、边框 #DFE1E6、主操作 #3478F6。待确认使用琥珀色状态点与文字，完成使用绿色图标与文字。
- 字体为 Inter 与系统中文字体。字号以正文 14–16、对象标题 18、按钮 14 为基准，8px 间距；照片与可编辑文字/控件分离。
- 黄雨衣人物「小雨」和咖啡馆草图继续作为独立主体/构图参考；图中 768×432、2048×1152、积分数仅为同一流程的示例，不代表实际模型报价或能力。

## 三张连续状态

1. `01-review-draft.png`：预览 v1 待确认。左侧参考保留，右侧为生成结果。大图下方是唯一一组「就用这张 / 这里要改 / 停」。紧邻按钮说明「确认后生成正式尺寸」，显示 2048×1152 与预计 6 积分。右侧聊天保留关联缩略图、版本、状态与「定位到预览」，没有第二组确认按钮。无计划卡或额外确认弹窗。
2. `02-refine-draft.png`：用户已点「这里要改」，在咖啡馆门口灯光处涂抹。原预览与人物保持可见，标记作为独立覆盖层。画布显示「修改中 · 尚未生成」，右侧唯一输入框显式引用「画面 01 · v1」与「涂抹 · 门口灯光」，文本为「只把门口灯光调柔和，人物和构图不变。」。发送动作改为「生成修改预览」，发送前显示预览预计消耗；未发送不生成。未发送文字与显式引用自动保存；涂抹只在当前编辑会话保留，取消修改不提交生成。
3. `03-confirmed-render.png`：一次修改已提交并获得预览 v2，用户又在其确认带点过「就用这张」。本屏聚焦版本关系，左侧展示保留的 v1 历史预览，主体与构图来源收成两个独立缩略图；右侧为新版 v2。当前显示「预览 v2 · 已确认」，下面显示「正式版生成中 · 2048×1152」。不再出现可重复点击的接受按钮，也不把仍在生成的正式版标成完成。右侧时间顺序清楚显示修改请求、v2 关联卡、确认记录和生成状态。对话输入继续可用；正式版未就绪前没有自动引用一个不存在的结果。

## 交互细则

- 同一份文档保留一条主对话；手动生成默认小入口，展开为独立参数表单。纠正 v3 的强制互斥规则：打开手动面板不自动隐藏或提交 Agent 输入；两份输入草稿各自保留。
- 界面严格使用「草图」表示用户绘制的构图、「低清预览」表示模型小图、「正式版」表示正式输出；「输入草稿」仅表示尚未发送的文字、引用和标记。
- 画布的三按钮绑定准确对象和版本。右侧卡片点击「定位到预览」后，将该对象适配到可见区域并突出确认带。预览移出视口时右侧显示待确认提示，不另复制一组批准按钮。
- 点击「就用这张」即对已展示尺寸、预计费用的一次正式生成作出确认，不额外弹计划或二次确认。报价改变时原按钮暂停，并更新报价后等待重新点击；不静默提价。
- 「这里要改」只进入编辑，既不重新生成，也不自动提交输入框里已有文字。已有未发送文字时保留原内容，不用系统建议覆盖。新预览生成后旧版本保留，旧卡显示「已有新版 v2」并定位到最新版；旧按钮失效，不能被误点重新提交。
- 「停」终止当前创作任务的自动推进，保留已完成预览；隐藏面板、切换手动生成、刷新不等于停止。已提交任务可请求取消，但不能承诺已发生费用退回。
- 若正式尺寸通过重新生成获得，确认带需要补充「细节可能变化」；只有模型能力已验证时才能写成无损增强。本轮示例仅表达正式尺寸请求。正式生成中保留确认预览作为参照。正式结果完成后作为新对象放在它右侧，标明「正式版 · 尺寸」，保留低清预览与来源；下一轮使用具名、可移除的正式结果引用，选中别的对象不会偷偷替换引用。
- 输入「继续」不能接受草稿，只提示定位到当前确认带；三按钮之外的聊天信息不会隐式接受任何版本。
- 刷新恢复当前等待/修改/生成状态；恢复未发送文字与引用只恢复内容，不执行动作，不重复扣费。涂抹、蒙版和笔画不跨退出/刷新持久化；若恢复在局部修改等待点，提示「请重新标记修改范围」，不降级为整图生成。展示「已恢复 · 等待确认」等明确状态。
- 若来源对象被手改，暂停关联任务并说明冲突，不覆盖。生成失败保留预览与失败说明；重试由用户明确触发，无自动无限重试。
- 视频沿用同一确认带：先确认首帧，再逐段最短低清预览；下一段未生成时只显示等待；全部低清片段均确认后，才按顺序生成正式视频。正式段落的衔接取决于真实模型能力，不能承诺低清与重新生成高清的尾帧完全一致；本轮不新增该承诺。

## 素材与实现边界

使用内置 imagegen 编辑既有设计稿。照片、草图为图片素材，标题、按钮、引用标签、状态、涂抹覆盖层为将来需要实现的交互组件；本轮不交付可编辑图层或可运行原型。不直接操作即梦账户、不提交真实生成。

静态设计检查不能证明窄屏、键盘操作、状态恢复、并发冲突和实际费用正确。窄屏应由右侧面板切换为抽屉，确认带保持与结果关联且可见，不压缩至无法阅读。
