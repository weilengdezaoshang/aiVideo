## 0.1 2026-09-12 缺陷修复与闭环完成记录

本轮以"实际调用链与验收证据"为准核查前期声明，修复以下已复现缺陷并接通约定闭环：

### 调度与页面阻塞（修复）

- 缺陷：`POST /api/evals/v1/runs` 返回 202 却同步执行整个批次（time.sleep 轮询阻塞事件循环）；
  `cancel` 接口固定返回 409，无真实取消。
- 修复：新增 `evaluation/scheduler.py` 受控后台执行器（固定大小 ThreadPoolExecutor、并发上限
  `EVAL_MAX_CONCURRENT_RUNS`、同一 run 独占执行、排队/执行中去重）。创建接口持久化后立即返回 202。
- 取消：排队中直接置 cancelled；执行中写 stopping 并经 cancel_check 协作式停止派发；
  已发出的外部请求保留预算预留并按 unknown 对账，不提前释放并发槽位（worker 退出才归还）。
- 重启恢复：mock/replay 无外部副作用安全重新入队；live 保持 interrupted 等待人工对账，绝不盲目重提。
- 验证：`tests/backend/test_scheduler_budget_gate.py`（调度器非阻塞/重复提交拒绝/取消/重启恢复 18 测试）；
  本地 7802 实例端到端验证创建→202 立即返回→轮询→completed→报告/门禁/取消语义。

### 预算账本（修复）

- 缺陷（已复现）：同 scope 两个 `BudgetLedger` 实例各持实例级锁，上限 1 元被预留 1.5 元。
- 修复：锁按账本文件路径进程级共享（`ledger_lock`），同 scope 全实例互斥；`BudgetLedger.open()`
  提供进程内唯一实例；实例间通过日志增量 `_sync()` 保持一致。金额一律 `Decimal(str(x))` 比较，
  拒绝负数/NaN/inf/非数值。新增 `mark_sent`（发送标记，崩溃后按 unknown 对账）、结算口径
  `billed/provider_reported/estimated` 分离、`import_billing` 账单导入对账、
  `reserve_chained`（run+项目两级预算原子预留，任一拒绝则回滚，不产生部分预留）。
- 验证：`test_multiple_ledger_instances_same_scope_cannot_overspend`、
  `test_chained_project_budget_blocks_second_run`、`test_invalid_amounts_are_rejected`、
  `test_sent_then_unknown_keeps_reservation_and_no_auto_retry`、`test_settle_basis_distinction_and_billing_import`。

### 真实裁判与预算闭环（接通）

- `create_run` 解除"仅 stub"硬限制：`judge=vlm` 必须 live 模式 + 正预算 + 配置冻结进 manifest.grading
  （model/temperature/maxAttempts/maxTokens/promptVersion/preprocessingVersion）。
- 裁判的全部真实调用（含修复重试）经 `BudgetedSyncTransport` 走预算网关：每次调用独立预留、
  attempt 递增；价格未登记（PRICE_UNKNOWN）或预算不足（BUDGET_EXHAUSTED）在发送前拒绝并记为裁判失败。
- usage 修复：裁判多次尝试的 usage 全部保留（`usage_attempts` 聚合，raw 保留）；
  缓存条目保存首次计算的 usage 与费用口径（修复首次计算丢 usage）；
  缓存命中方带 `cacheSource` 引用且不重复记账。错误结果默认不入缓存。
- 校准闭环：新增 `evaluation/calibration.py`（人工独立标注导入、混淆矩阵、split 保留）+ API
  `GET/POST /api/evals/v1/calibrations`；vlm 裁判无匹配校准记录或缺陷召回 < 0.8 时质量门禁 inconclusive。
- 验证：`test_required_review_incomplete_blocks_pass_and_human_fail_verdict_blocks`、
  `test_calibration_absent_keeps_quality_gate_inconclusive`、缓存 usage 测试。

### 人工审核 → 门禁（接通）

- 门禁此前只检查 disputed。现读取全部审核任务与追加式裁决：
  必审任务未完成裁决 → inconclusive；人工最终裁决 fail → block；裁决 undetermined → inconclusive。
- 审核任务状态迁移（领取/提交/争议/裁决）在按任务 ID 的进程锁内完成，原子写 task.json；
  提交意见校验领取人身份（租约与身份关联）；裁决绑定 rubric 版本与素材。
- run 完成后调度器按版本化抽样策略自动创建审核任务（必审=fail/undetermined、风险抽样、随机抽样，
  种子确定性可复现，抽样依据写入任务 `sampling` 字段；`EVAL_REVIEW_SAMPLING` 可配）。
- 验证：门禁必审/人工失败测试 + `test_scheduled_reviews_created_by_sampling_policy`。

### 严格回放（修复）

## 2. 差距与实施顺序（对应技术方案 §20）

推荐纵向切片优先：先让**一条数量用例**走通"冻结快照 → mock 执行 → 类型化判分 → 完整状态报告 → 旧数据导入"，再横向扩展批次、回放与预算。理由：P0 的数据模型是后续所有阶段的地基；先打通单用例能最早暴露 schema 设计问题。

```text
P0 证据与口径   models/datasets/artifacts/类型化评分/完整报告/legacy 导入
  └→ P1 严格回放与预算   recorder/replay/budgets/禁网 guard/崩溃恢复
       └→ P2 追踪与人工   步骤 span/审核裁决/线上问题转用例
            └→ P3 可视化与比较   /api/evals/v1 + 中文页面 + 比较 + gate + 第三方适配
                 └→ P4 能力扩展   视频/编辑评估器、裁判校准、压缩实验
                      └→ P5 持续运营   监控/保留/备份恢复/导出（事务库迁移按 §17.3 触发条件另评）
```

阶段门槛（§20）在进入下一阶段前必须自检：

- P1 前：不把平台标记为"支持确定性回放"。
- P2 前：不把人工打分字段等同于多人审核系统。
- P4 前：不宣称视频全维度评测已完成。

## 3. 不可突破约束清单（实施中逐条自检）

来自任务要求与技术方案 §1.3，编码时逐条对照：

1. 新增前端业务代码全部 TypeScript，禁止 `any`；纳入现有 typecheck/lint/test。
2. 复用 `app → jobs → provider → storage` 单一业务链路；不复制第二套生成逻辑；评测通过注入配置/transport/时钟/事件记录器观察行为。
3. 现有 `/api/generate`、`/api/jobs`、`/api/events` 与 data 格式语义不变；变化必须有兼容测试（COMPAT-01）。
4. 主应用保持单进程 JSON 存储；评测数据写 `data/evaluation/`（Git 忽略），不碰真实用户画布/任务/素材；不增加 Uvicorn worker。
5. 不改变抠图识别取消/迟到结果防护/线程槽位语义；不缓存或恢复生产 mask、选区、笔画草稿（CUTOUT-01 回归保护）。
6. Mock/stub 分数不进入质量排行；缓存/回放不算独立真实试验；固定 seed ≠ 云端输出相同。
7. 回放禁网：翻译、裁判、模型发现、媒体下载、遥测导出全部阻断（REPLAY-06）；开发依赖安装与回放运行分离。
8. 默认真实预算 0；未知用量/费用保持 null；`unknown_external` 不盲目重试、不释放预留（BUDGET-02/03）。
9. 评分缓存键覆盖素材/预处理/检查项/规则/模型修订/语义配置（CACHE-02）；普通缓存 ≠ 完整录制包。
10. 旧运行与原始证据可追溯；重跑/重新评分/审核修订均建新版本（REVIEW-02）。
11. 项目证据库权威；Promptfoo/Langfuse 仅适配展示，不得重复执行或重复记账。
12. 不自动使用环境密钥调用真实模型；不发起付费调用/公开部署/通知/周期任务。
13. 第三方依赖核对官方文档、锁定验证版本；不写 `latest`。
