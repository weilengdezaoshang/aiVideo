## 1. 产品定位与首版完成标准

一个以画布为文档、让用户通过直接操作与受限创作助手生成、加工和整理视觉素材的平台。首批服务开发者本人和体验者，商业用户画像仍待验证。

首版完成标准：用户从工作台进入“我的画布”，创建、命名并重新打开同一文档；完成一轮四方向图片生成；选取图片，经蒙版确认得到相邻的透明图片；通过一次带显式引用的助手操作完成同一闭环；下载原始素材。刷新、断线、失败和离开页面后，已保存内容与已产生资产可恢复，未知请求不会被自动重提。

真实四方向生成、蒙版编辑质量和 Agent 模型调用需要分别验收。交互演练中的示例图片、状态切换与本机存储只用于评审，不能替代这些验收。

### 1.2 不可悄悄改变的约束

1. 工作台 → 画布 Tab → 我的画布 → 新建或打开 → 编辑器。
2. 左侧悬浮栏只有本地上传、导入资产、添加画板、添加文字四项。
3. 输入框位于对话栏底部；对话栏收起或窄窗折叠时，输入框回落画布区域底部居中。右侧展示消息、任务和结果。（2026-09-10 负责人修订，原“输入框在画布区域底部居中”，见 §4.1 修订记录）
4. 一轮文生图是同一任务的四个不同创意方向，每方向一张；画布横排成组、对话同组预览。
5. 四个占位同时出现、同步表达本组状态，不用逐张队列或虚构百分比。
6. 单图选框贴边，四角圆形、边中点胶囊控制点，图片标签在左上，操作栏在下方。
7. 蒙版出现和编辑不生成结果；只有蒙版栏“抠图”按钮显式提交才生成透明素材。
8. 原图保留；抠图结果默认在源图右侧；组内后续图片顺延，派生结果不是第五个创意方向。
9. 四个候选方向不是分镜；分镜需另定义镜头顺序和结构。
10. 目标后端包含 Python。文生图、文生视频、抠图流程已有用户验证记录；图生视频及其他编辑能力单独验证。
11. 用户后续已确认视觉方向为“专业创作工作室”：中性灰白与少量蓝色强调，浅色默认；仅编辑器可切深色并记住偏好。工作台、我的画布保持浅色；这些编辑器与工作台要求已确认。介绍页最新暗色方向仅为本轮可评审实现，不跟随编辑器深色开关，也未获新的用户确认。
12. 用户要求介绍页参考即梦的构图，保留 aiVideo 品牌与现有展示素材；不使用即梦媒体，不复制视频能力宣称，不改变工作台、列表与编辑器业务范围。

## 2. 范围与分期

| 范围 | 首版必须做 | 后续做 / 暂不开放 |
| --- | --- | --- |
| 入口 | 介绍页、工作台概览、画布 Tab、列表、创建、重命名、稳定地址、返回 | 模板、文件夹、社区、商业场景入口 |
| 画布 | 图片与视频对象、平移缩放、选择、移动、画板与文字基本编辑 | 拆组、复杂吸附、画板裁剪、多人协作 |
| 图片生成 | 固定四方向、组标题、四占位、同步结果、失败保留 | 用户编辑单个方向、局部补生成、扩图、超清、智能改图、多角度 |
| 抠图 | 识别、画笔/橡皮、蒙版撤销重做、显式提交、相邻派生资产、失败恢复 | 智能辅助选区、批量抠图、发丝精修承诺 |
| Agent | 一张显式引用、有限计划、识别蒙版、等待用户、生成与落位、恢复步骤 | 自动循环、多图批处理、跨画布操作、网页搜索、自动合成与图像语义理解承诺 |
| 视频 | 保留已验证的文生视频能力入口；资产导入、画布视频对象、预览和原文件下载 | 独立新版视频页重做、图生视频、时间线、拼接、配音、分镜 |
| 导出 | 选中一个图片/视频下载原文件；透明结果下载 PNG | 整张无限画布合成、画板渲染导出、批量 ZIP |

页面补充建议：独立产品首页先展示介绍页，“进入工作台”进入概览，再由画布 Tab 进入列表。概览包含画布入口、最近文档及已有图片/视频入口；浏览介绍页、工作台或列表均不自动创建文档。此前“工作台首次默认进入列表”的推荐相应修订，既定的工作台→画布 Tab→列表→编辑器层级保留。

图片、视频入口先连接已有可用能力。不能在新工作台把旧版单张/串行文生图包装为已满足四方向规则：新入口未通过四方向验收时显示能力不可用，旧实验能力可保留在明确标识的旧入口。首页快捷输入暂不开发，减少两套重复表单。

## 3. 页面与导航

43 张既有线框表示页面和组件状态，不是 43 个独立页面。补充介绍页后，以介绍页、工作台壳、编辑器三个布局承载四个页面职责。

| 页面 / 建议地址 | 目的与主要操作 | 入口 | 出口 | 核心状态 |
| --- | --- | --- | --- | --- |
| 介绍页 `/` | 查看作品首屏、素材大图、原型编辑器预览与助手步骤，开始体验 | 打开产品首页 | 进入工作台、查看示例、阅读 PRD | 三场景切换、作品大图 dialog、章节定位 |
| 工作台 `/workspace` | 选择模块、找到最近文档与画布入口 | 介绍页、产品导航 | 画布 Tab、已有图片/视频入口、设置 | 服务正常 / 某能力不可用 |
| 我的画布 `/workspace?tab=canvas` | 找到、创建、继续文档 | 工作台 Tab、编辑器返回 | 新建成功 / 打开卡片进入编辑器 | 读取中、空、列表、失败、创建中、创建结果待确认 |
| 编辑器 `/canvas?doc=<id>` | 生成、加工、组织和下载当前文档素材 | 列表、稳定链接 | 返回我的画布，保留 Tab | 读取中、空、有内容、任务中、保存中、保存失败、文档不存在 |

介绍页首屏展示定位与可切换作品场景，不展示内部评审控制台、虚构商业数据或未验证能力。“查看示例画布”只创建明确标识的本机示例。独立原型以全窗口呈现产品；模拟响应与失败开关默认折叠，有待响应时提供明确的模拟结果入口。介绍页、工作台、列表适配窄屏；编辑器保留桌面布局，窄屏滚动限制在编辑区域内。

四个页面的主题职责不同：介绍页说明产品与展示素材，自带贯穿首屏与后续章节的暗色影像展厅；工作台组织入口与最近文档，画布列表管理文档，两页保持浅色；编辑器承载持续创作，提供浅色 / 深色切换。介绍页不跟随该开关。进入或返回其他页面不清除编辑器的主题偏好，也不因主题变化创建文档。

画布名称本轮建议为 1–100 字符，去首尾空白；空名称保留“未命名画布”。点击新建产生一个幂等创建请求，收到 ID 后导航；连续点击期间禁用新建。网络超时保留请求标识并查询同一次创建，不新建第二份。列表读取失败显示重试，不呈现“暂无画布”。列表加载期间允许新建，但创建接口不可用时说明原因。

返回按钮显示“返回我的画布”，目的地明确。变更保存成功才返回；保存失败显示“留在画布 / 重试保存 / 放弃未保存的修改”。放弃仅影响未提交的本地文档操作，不取消已接受任务、不删除成功资产。不存在与读取失败分开，不能用新建文档兜底。

### 3.1 最新介绍页范围

按用户要求参考已观察到的 [即梦官方介绍页](https://jimeng.jianying.com/) 首屏作品构图，使用 aiVideo 自有品牌与已有 Unsplash 展示素材；后续功能区围绕本项目组织。本轮首屏左侧以“让灵感 / 自由成形。”固定两行呈现，左下为海洋、建筑、花卉横排缩略图与说明；首屏仅顶部右侧暖白“开始创作”入口，不设底部白色操作卡或伪输入框。深炭灰、暖白文字与原色作品贯穿后续章节。

用户拒绝上一版介绍页主题并指出底部白色操作区突兀后，本轮实现暗色影像展厅作为可评审方向；异步主题偏好尚未回复，不视为用户已确认。范围仅介绍页，工作台、列表与编辑器不随本轮扩大修改。

后续四张素材卡片支持大图 dialog，关闭按钮和 Esc 关闭后焦点返回触发卡片；明确照片仅用于展示视觉风格，不是当前提示词或同一任务的四张生成结果。智能画布章节展示当前原型的实际编辑器截图，点击截图或入口进入 `example`。Agent 章节以静态步骤说明显式引用、准备蒙版和等待最终“抠图”提交，不自动执行任务。

章节锚点在介绍页内定位，产品入口沿用工作台与示例导航；从编辑器离开仍经过原有保存与草稿保护。浏览和放大不调用模型、不创建文档；默认内容静态可见。首屏仅首次进入以 WAAPI 展示图片 1000ms 缩放与标题两行 620ms 错开入场；图库及实际界面图通过 IntersectionObserver 首次进入视口时各播放一次。三层场景图片先 decode，再以请求序号防止快速点击乱序，切换 active class 触发 650ms opacity 过渡，同时同步 aria-hidden、说明和选中态。后台、离开介绍页或 pagehide 时取消动画、断开观察并作废待完成切换；减少动态偏好即时取消动画和过渡，重新允许动态不重播首屏。悬停放大仅在 hover:hover 且 pointer:fine 时启用，无自动轮播。视频、社区和其他即梦能力不因参考构图而纳入当前承诺。

介绍页标题独立使用 `GalleryDisplay`：官方 Noto Sans SC 实例化为真正 500 字重的 `display-medium.ttf`；编辑器沿用原 `display.ttf`。首屏 h1 字距为 `-.015em`；章节 h2 字重 500、字距 0，字号按 `landing.css` 响应式规则缩放（章节 `clamp(32px,3.4vw,48px)`，桌面常见约 40–48px；收尾 `clamp(32px,4vw,52px)`）。桌面章节正文 16px / 1.8，手机首屏副标题 14px、章节正文 14px / 1.85；素材说明、截图注释与页尾备注统一 12px。

大图预览新增 200ms 进入、150ms 退出，以 opacity 与 scale(.98) 配合遮罩同节奏变化；Esc 与关闭按钮共用退出流程，完成后恢复触发卡片焦点。反复打开时取消旧动画，并用序号防止旧关闭回调关闭新预览；减少动态偏好下直接关闭。章节采用 CSS 原生 `scroll-behavior:smooth`，减少动态时为 `auto`；跨页返回介绍章节平滑定位，返回介绍首屏即时定位。跨页仍经过既有离开保护。本轮不增加工作台淡入。 本次仅同步独立原型的字体、大图过渡与章节滚动，检查见 [字体与过渡同步检查](./reviews/v0.5/字体与过渡同步检查.md)。

此更新落在独立 HTML 原型；工作台、列表、四方向、显式蒙版和 Agent 状态机不变，生产实现仍按本 PRD 验收。本轮证据单独记录于 [即梦参考介绍页检查](./reviews/v0.5/即梦参考介绍页检查.md)。

## 4. 编辑器布局与直接操作

### 4.1 布局建议

顶栏 56–64px；右侧对话栏默认 320px，可在 280–360px 间调整；左侧工具条宽 48–56px，与画布边缘间距 16px；输入框位于对话栏底部（修订后），重绘/蒙版工具栏显示时临时让位并预留操作浮层安全区。正文 14–16px，辅助说明 12–13px；交互目标桌面至少 32px，触屏 44px。正文对比目标 4.5:1，控件/选框 3:1；状态同时用文案和形态辨认。

桌面最小建议宽度 1024px。窄窗口允许主动收起对话；对话收起或折叠时输入框回落画布底部居中，展开后回到对话栏底部。移动设备可阅读 PRD，完整画布编辑首版不承诺移动支持。工具栏先贴图下方，左右夹紧到画布安全边界；下方不足时轻移视口腾出空间，必要时使用画布内底部停靠栏并显示对象名，不能覆盖对话或输入框。空间不足时操作栏可横向滚动，但“添加到对话 / 抠图 / 下载”应优先可见。

### 4.1.1 已确认的视觉主题与偏好

采用专业创作工作室的中性灰白界面，蓝色仅强调主要操作、选中与焦点。浅色为默认；编辑器提供显式切换，工作台和画布列表始终使用浅色。介绍页的暗色影像展厅属于章节设计，不跟随编辑器开关。视觉内容本身不因主题滤色或反相，主题不改变生成资产的像素或导出结果。

| 语义 token | 默认浅色 | 编辑器深色 |
| --- | --- | --- |
| 背景 `--studio-bg` | `#F5F5F7` | `#191A1E` |
| 面板 `--studio-panel` | `#FFFFFF` | `#25262C` |
| 正文 `--studio-ink` | `#202124` | `#F0F1F4` |
| 强调 `--studio-accent` | `#356DF3` | `#356DF3` |

偏好保存与画布保存分开。用户改成深色后，退出编辑器会看到浅色工作台；再打开同一或另一画布时沿用深色偏好。未保存过偏好时使用浅色。主题切换不清空未发送文本、素材引用、选中对象、蒙版笔画或任务，不重新生成、不重新提交、不改变对象几何。主题偏好无法持久化时，本次选择仍可生效，但不能显示为“偏好已保存”。

两种主题均需保持普通工具栏 / 蒙版栏、选框、四图生成状态、失败状态及透明棋盘的辨识度。`产品效果-创作平台-v0.5.html` 中的 DOM、CSS tokens 与偏好存储属于可交互原型；生产端尚未落地。下列主题验收为生产要求；本机 HTML 的抽样验证单独见 [主题同步检查](./reviews/v0.5/主题同步检查.md)，不表示生产已经通过。

#### 4.1.2 输入框位置修订（2026-09-10）

负责人提出并确认：打开对话栏时画布底部输入框隐藏，输入框作为对话栏底部的一部分呈现；对话栏收起或窄窗折叠时，输入框回落画布区域底部居中，保证任意时刻可输入。本条修订覆盖原约束 3 与 §4.1 中“输入框持续相对画布居中”的描述，重绘/蒙版工具栏显示期间输入框仍临时让位。实现与本文档、技术方案同批更新。输入卡样式参考即梦：创作模式与尺寸比例以幽灵下拉呈现，生成主按钮置于卡片右下。

### 4.2 选择、移动、画板与文字

| 操作 | 本轮建议规则 | 失败或取消 |
| --- | --- | --- |
| 单图选择 | 点图选单图；点组标题选组；单图选框和组边界不同 | 点空白或 Esc 取消选择 |
| 组移动 | 拖组标题移动整组；组内图片可选中处理，首版不自由重排 | Esc 回到拖动前位置 |
| 平移 | 空格+拖动或中键；焦点在输入/文字时不触发 | 松开恢复原工具 |
| 图片缩放 | 本轮建议等比缩放，控制点屏幕尺寸固定；组布局随后重排 | 不改原资产分辨率 |
| 本地上传 | 用户选择 PNG/JPEG/WebP，建议单文件不超过 40MiB；真实限制由能力契约返回 | 格式/解码/上传失败原画布不变；取消不新增 |
| 导入资产 | 选已有资产，新建当前文档对象，复用资产本体 | 同次点击幂等；再次主动导入允许第二个实例 |
| 添加画板 | 当前视口中心新建 1024×1024 逻辑画板，名称“画板 1”；背景容器不裁剪、不自动收养重叠对象 | 可重命名、移动和改尺寸；不承诺合成导出 |
| 添加文字 | 视口中心插入可编辑文字；系统字体、默认 32px、左对齐、黑色；多行纯文本 | 双击编辑；Esc 恢复本次编辑前内容；点击外部提交；空文本离开时不保留空对象 |

图片操作栏的有效能力为“添加到对话、抠图、下载”；其余 v0.3 截图占位在规格对照中保留“待确认”，本轮建议正式首版隐藏，不提供无反馈的假按钮。这是对旧线框展示方式的建议调整，不代表删除已确认能力。

## 5. 四方向生成

### 5.1 方向与提交

输入区提供“生成图片 / 创作助手”模式，本轮建议默认生成图片，避免任意文字被模型自行决定为付费生图。用户输入需求、选可用尺寸/比例后，点击“生成 4 张”。数量固定显示“4 个方向 × 每方向 1 张”。

本轮建议由文本规划器输出四条结构化方向：共同主体、硬约束、方向标题、变化维度、具体提示词。四方向围绕构图、光线、场景或表达方式变化；用户指定的风格和主体不能被强行替换。完整描述可在任务详情展开；首版不增加必须预审四条提示词的步骤。方向规划失败则整组失败，不调用图片模型。示例方向名称仅帮助理解，不是固定四风格模板。

“不同 seed”不足以证明“四个方向”。上线前使用一套版本化评估集验证共同约束与方向差异；建议起始 10 个需求、40 张结果，逐组人工标记“主体/硬约束是否保留、方向说明是否不同、图像是否体现差异”，不编造已通过比例，不自动花费调用进行质量重抽。

### 5.2 状态与恢复

| 当前状态 | 触发 | 界面与后续状态 | 恢复 |
| --- | --- | --- | --- |
| 空输入 / 服务不可用 | 查看输入 | 禁用提交并说明原因；可继续浏览 | 修改输入或配置可用服务 |
| 提交中 | 用户生成 | 原位同时创建四个准备占位；一个需求消息、一个任务卡 | 不确定时查询同一请求 |
| 准备方向 / 整组等待 | 服务接收，尚未开始执行 | 四格统一“准备中”或“等待开始”；不显示某格正在生成 | 可取消；不编造排队位置 |
| 整组执行中 | 后端确认整批执行启动 | 四格统一深灰“生成中…”；对话同组 2×2 预览 | 断线改为“连接中断，正在查询”；本轮不自动重提 |
| 完成 | 四槽位均完成、资产可读、落位事务成功 | 原位发布四图，显示“4/4 已生成” | 点击任一图继续加工 |
| 部分完成 | 本次尝试所有槽位已终结，仅部分有效 | 有效图与失败槽位同时展示，保留 slot 位置和原因 | 首版建议“另生成一组 4 张”，旧组和成功图保留；新组有关联，并明确将产生新的生成调用，实际费用由所选服务决定 |
| 失败 | 无有效结果且明确终结 | 四个错误格、原需求保留 | 用户显式重生一组；不自动调用 |
| 结果待确认 | 请求/供应商结果不明 | 显示查询入口，保留 groupId/requestId | 只查询；允许离开和继续手动编辑，显示最近确认状态；后端确认未接受后才可安全重提 |
| 已取消 / 停止后续处理 | 用户取消且后端回应 | 不把取消写成已退费；已完成资产保留 | 已有产物可从资产记录取回；不自动插入被撤销的组 |

默认正常任务只在整组终结后发布图片，不逐张显露“1/4 完成”。后端可先持久化已返回的资产，以抵御崩溃，但前端共同呈现。失败槽位补生成延期：它需要独立 attempt、供应商能力与计费说明，不能模糊地塞入普通“重试”。

## 6. 抠图状态机

| 状态 | 用户动作 / 条件 | 反馈与下一步 | 保存与恢复 |
| --- | --- | --- | --- |
| 普通选择 | 图片工具栏“抠图” | 开始识别蒙版，原图保持可见 | 锁定源 assetId/version，不生成新图 |
| 识别中 | 服务处理 | “识别主体中”；主按钮禁用 | 可退出；晚到响应不得对已关闭的会话自动落位 |
| 识别失败 | 无有效蒙版 | 明确失败，显示“重新识别 / 返回图片” | 原图不变，不展示假蒙版 |
| 蒙版就绪 | 识别成功 | 半透明叠加+“高亮区域将保留”；画笔加选区，橡皮去选区 | 此时仍无透明结果 |
| 蒙版编辑 | 绘制、撤销、重做 | 只修改选区；蒙版本地历史与画布撤销隔离 | 建议笔画结束保存草稿；刷新恢复最近已持久化版本 |
| 退出编辑 | 关闭或 Esc | 默认先保存草稿，成功后退出并提示“草稿已保留”；仅保存失败时显示“继续编辑 / 重试保存 / 放弃本次蒙版” | 保留草稿不会自动生成；再次进入提示继续草稿 |
| 生成中 | 点击蒙版栏右下角“抠图” | 固化当前蒙版版本，按钮“生成中…”，锁编辑与重复提交 | 保留源图和蒙版；服务端任务持久化 |
| 生成失败 | 明确失败 | “返回蒙版”回编辑态；本身不重试 | 用原草稿修正后再次显式点击“抠图” |
| 完成 | 透明 PNG 持久化且对象插入完成 | 选中源图右侧新结果；对话展示预览和“来自图片 N” | 原图不变，来源、蒙版版本、操作记录可追踪 |

组内顺序：图片1 → 图片1派生结果1 → 图片1派生结果2 → 图片2 → 图片3 → 图片4（按派生创建顺序追加）。四个创意 slot 永久不变，显示列表可增长。插入后保持四张原候选的宽高；容器扩展，不得等分五列把原图压窄。相邻间距建议 24 个世界坐标单位；源图及其组以外对象不为此次插入自动移动。若扩展与其他组相交，给出“整理位置”建议，保持来源与用户原布局可预测。

独立图片同样在右侧放置；源图若在任务期间已移动，用完成时的源图位置计算。源对象已删除或提交已撤销时，保留资产并显示“结果已生成，尚未加入画布”，用户可显式放置；禁止复活已删对象。撤销只移除这次派生对象及其布局变更，不撤销付费请求、不删除源资产。

## 7. 首条 Agent 完整用例（本轮推荐）

用例 A：把显式引用的一张图片的主体抠出，并放在原图旁。用例 B：抠主体后再生成四个背景方向。推荐 A：能验证引用、结构化工具调用、人工暂停、结果持久化与继续编辑；B 增加方向规划、生成并发和背景质量依赖，留到下一阶段，并且仍不等于自动合成成图。

| 步骤 | 用户能看到什么 | 执行边界 |
| --- | --- | --- |
| 引用 | 选图后“添加到对话”，输入区出现可移除的缩略图与名称 | 显式引用优先；切换选中对象不偷偷替换引用；首版仅一张 |
| 提出需求 | 输入“把这张图的主体抠出来，放到旁边” | 模型不凭空猜对象；没有引用时先要求选图，不执行 |
| 计划 | 回复“识别主体 → 请你检查蒙版 → 生成透明图片并放到右侧”；卡片说明源图、1 张输出和需人工确认 | 一次计划仅当前画布的一张图；无额外生图轮次 |
| 准备 | 意图完整明确、真实计划与服务端校验通过后，自动准备最多一次蒙版；显示真实识别状态 | 歧义或混合超范围请求先澄清，零工具调用；手动与助手共用接口 |
| 等待用户 | “请在画布检查蒙版，点击蒙版栏‘抠图’继续” | 不自动提交；聊天“继续”只定位到蒙版，不绕过按钮 |
| 结果 | 用户提交后，显示生成与落位状态；完成显示透明预览、来源和定位入口 | 资产完成而未落位时不能宣称整个任务完成 |
| 再次修改 | 用户引用实际结果或返回原图调整 | 下一轮形成新计划；不复跑已完成步骤 |

自动准备就绪不能抢走用户后续选择、文字编辑或其他蒙版焦点；此时保留当前工作，计划卡显示“检查主体选区”。点击该入口仅定位源图与已有蒙版。取消或退出后再次恢复不自动识别第二次。

模型层要输出受 schema 限制的计划；服务端验证工具白名单、docId、assetId/version、计划状态与操作上限。不能把前端关键词分支或模板回复验收成 LLM Agent；模型超时、无效工具参数、越权引用有独立错误测试。首版不要求视觉理解，文案不能说“我看见图里有……”。

进行中允许编辑下一条草稿，暂停发送第二个执行请求，避免上下文与计划交错。停止不删除已完成产物；刷新只恢复消息、步骤和人工暂停点，不自动重提模型或调用工具。

## 8. 视频与下载

首版视频资产路径：已验证文生视频入口 → 平台资产 → 导入资产 → 当前画布对象。文生视频没有源图时显示“来源：文字描述”；不能凭选中图片伪造为图生视频。保存任务、提示词、产物与使用该资产的文档关联。已有视频对象用海报帧、时长、文件格式与来源辨认。

单击选择视频对象，拖海报外框移动；“播放预览”打开带原生控件的预览层。关闭停止播放，焦点返回原对象；播放器内拖动进度不移动画布。首版不做内嵌多路自动播放。

图片和视频下载原文件，透明结果固定 PNG；返回的是资产文件而非截图或棋盘格。开始下载反馈“已开始下载”，不宣称用户已成功保存磁盘。文本和画板仅随文档保存，不能误显示图片下载可用。

## 9. 保存、恢复与可观察验收

保存状态与任务状态独立：文档可以已保存但图片仍在生成。建议 1 秒防抖提交文档操作；本机草稿先持久化，服务端确认 revision 后才显示“已保存”。本机草稿写失败时明确提示刷新会丢失当前修改，不能承诺离线全量恢复。大图片、视频不内嵌文档 JSON。

SSE 断线后先恢复同一文档快照与任务，再按事件游标补齐；重复事件按唯一结果键忽略。离开页面不取消已接受任务。服务重启且供应商结果未知时查询原 requestId，不自动重发。双标签冲突用 revision 检测，保留本机草稿、重新加载服务端版本；不使用最后写入静默覆盖。

## 10. 仍需负责人决定的三项

1. 是否采用用例 A 作为首条 Agent 完整用例？推荐 A，后续再扩展四背景方向，避免首版跨越多个尚未验证能力。
2. 是否接受视频首版只复用已验证入口与资产预览链路？推荐接受，独立视频页重做与图生视频后置。
3. 是否接受“先验证四方向能力与 Python 任务核心，再迁移外壳，复用现有画布引擎”的实施顺序？推荐接受；具体供应商/模型在能力实验后决定，不能预先宣称支持。

除已明确确认的专业创作工作室主题与编辑器深色范围外，其余未确认的布局、文案、默认尺寸和重试方式继续以本轮建议给出，不为每项实施细节增加审批。负责人后续修改选择时，同步更新技术方案、验收与交互文档。
