# FRAYUNE 评测体系使用说明

> 前置:技术方案 [技术方案-完整评测体系-v1.0.md](./技术方案-完整评测体系-v1.0.md);实施状态见 [评测体系实施记录.md](./评测体系实施记录.md)。
> 所有命令均在仓库根目录、已准备 `.venv` 的环境执行(Python 3.11+,`npm install` 后前端构建可用)。

## 1. 启动与验证

```bash
npm run verify          # 全量门禁:typecheck + build:web + lint + node:test + ruff/pytest
npm run dev             # 启动主应用 http://127.0.0.1:7801(评测工作台在 /evals)
.venv/bin/python scripts/eval-replay-demo.py   # 零费用离线演示:录制→严格回放×2→参数差异定位
```

## 2. 数据集:校验与冻结(v2 用例格式)

v2 用例一行一条 JSON(schema 见 `evals/schemas/case-v2.schema.json`,示例见 `evals/datasets/core-zh.jsonl`):

```bash
.venv/bin/python scripts/eval.py dataset validate evals/datasets/core-zh.jsonl
.venv/bin/python scripts/eval.py dataset freeze evals/datasets/core-zh.jsonl --id core-zh
# → core-zh@1 冻结;同内容重复冻结幂等;修改源文件后再冻结生成 v2,旧 run 不受影响
```

## 3. 评测运行(Mock / 严格回放 / live)

所有 run 由受控后台执行器调度(并发上限 `EVAL_MAX_CONCURRENT_RUNS`,默认 1;同一 run 独占执行):
创建接口立即返回 202,执行在后台进行;页面/CLI 轮询状态,取消与恢复见 §3.1。

```bash
# Mock(零费用;页面 /evals 也可发起)
.venv/bin/python scripts/eval.py runs create --dataset core-zh --run-id demo-1 --purpose "冒烟"

# 严格回放(禁网;需已录制的源 run;匹配协议 v2 含 query;未消费交互/新增出口→run 失败)
.venv/bin/python scripts/eval.py runs replay --source <live-run-id> --run-id replay-1
# 退出码:0 成功且全部交互消费;1 存在 trial 失败或回放完整性失败;2 配置错误

# live(真实费用!必须显式正预算 + 环境密钥;未登记价格的调用会被 PRICE_UNKNOWN 拒绝)
# runner.create_run(..., mode="live", provider="cloud", judge="vlm",       # judge 缺省为 stub
#     judge_config={"model": "qwen-vl-max-latest", "maxAttempts": 2},      # 冻结进 manifest.grading
#     budget={"maxCost": 5.0, "prices": {"generation": 0.5, "translate": 0.05, "poll": 0.0, "judge": 0.01}},
#     sandbox_config={"cloudVendor": "zhipu", "cloudBaseUrl": "...", "cloudModel": "...", "cloudTextModel": "..."})
# runner.execute_run("run-id")   # 全部真实调用经预算网关:先预留/标记发送,再请求,后按估算口径结算
```

多模态用例:`image_to_image`/`image_edit`/`image_to_video` 需在用例中引用已归档素材
(`referenceArtifactIds`,image_edit 需原图+PNG 蒙版两项);素材在 run 创建时复制进 run 目录并校验哈希,
执行时按 taskType 正确传参,缺失/不支持会显式拒绝,不会静默退化为文生图。

压缩实验:创建 run 时传 `compression={"enabled": true}`(默认关闭;版本冻结进 manifest);
用"原始 run + 压缩 run"配对出报告(§5 compression-report),质量下降超阈值禁止推广。
稳定性试验请传 `useGradeCache=False` 绕过判分缓存。

查看:`runs list` / `runs show <id>` / `runs report <id>`(报告版本不可变,每次生成新版本)。

## 3.1 取消、恢复与对账

```bash
curl -X POST http://127.0.0.1:7801/api/evals/v1/runs/<id>/cancel   # 排队→直接取消;执行中→stopping(协作停止)
curl http://127.0.0.1:7801/api/evals/v1/runs/<id>                  # progress 计数与状态(刷新页面可继续追踪)
```

- 取消语义:停止派发新 trial;已发出的外部请求保留预算预留并按 unknown 对账,不自动释放、不盲目重试。
- 重启恢复:mock/replay 自动重新入队;live 保持 interrupted,需人工核对 `externalTaskId` 后再处理。
- 预算对账:`GET /runs/{id}/budget` 返回逐笔预留(含 unknown);账单导入:
  `BudgetLedger.import_billing(reservationId, billed_amount, raw=...)` 升级为 billed 口径。

## 4. 旧数据导入

```bash
SWARMUI_ENV=development .venv/bin/python scripts/eval.py run --provider mock --out /tmp/legacy-evals --run-id old-1
SWARMUI_ENV=development .venv/bin/python scripts/eval.py judge /tmp/legacy-evals/old-1 --judge stub
```

## 5. 评测 API(/api/evals/v1,主应用自动挂载)

```bash
curl http://127.0.0.1:7801/api/evals/v1/datasets
curl -X POST http://127.0.0.1:7801/api/evals/v1/runs -H 'content-type: application/json' \
  -d '{"runId":"web-1","datasetId":"core-zh","purpose":"..."}'        # 202 后台执行,立即返回
curl http://127.0.0.1:7801/api/evals/v1/runs/web-1                    # 分母/指标/覆盖缺口
curl http://127.0.0.1:7801/api/evals/v1/runs/web-1/trials             # 逐 trial+评分
curl http://127.0.0.1:7801/api/evals/v1/runs/web-1/events             # 事件账本
curl -X POST http://127.0.0.1:7801/api/evals/v1/runs/web-1/gate       # 发布门禁(pass/block/inconclusive)
curl -X POST http://127.0.0.1:7801/api/evals/v1/comparisons -H 'content-type: application/json' \
  -d '{"baselineRunId":"a","candidateRunId":"b"}'                     # 配对比较(快照不一致→仅交集)
curl http://127.0.0.1:7801/api/evals/v1/runs/web-1/budget             # 预算账本读模型
```

审核:`POST /review-tasks` → `POST /review-tasks/{id}/claim {reviewer, expectedRevision}` →
`POST /review-tasks/{id}/reviews`(追加式;校验领取人身份)→ 可选 `POST .../dispute` →
`POST /review-tasks/{id}/adjudications`(append-only 裁决;失败裁决会使门禁 block);
冲突返回 409(REVIEW_CONFLICT)。run 完成后按抽样策略自动生成任务(必审/风险/随机,依据记录在
`sampling`;`EVAL_REVIEW_SAMPLING` 可配)。门禁读取审核水位:必审未完成→inconclusive,
人工最终裁决 fail→block,未定→inconclusive。
问题转用例:`POST /review-tasks/{id}/case-drafts` →
`POST /dataset-drafts/{draftId}/publish`(进回归数据集,DATA-02 校验把关)。

## 6. 第三方集成(适配,不重复执行)

- **Promptfoo(只读结果 provider)**:`backend/evaluation/integrations.py::build_promptfoo_tests(store, runId)`
  只映射项目内已有判定与素材引用;不启用额外 llm-rubric、不重复判分/记账(§3.3)。
- **Langfuse 导出**:`LangfuseExporter` 把评测事件翻译为 ingestion 批次,经 `Outbox.flush` 异步导出
  (有界重试、失败保留缓冲、不阻塞业务)。环境变量(不写入代码/数据集):
  ```bash
  export LANGFUSE_PUBLIC_KEY=...   # 凭据由部署环境注入
  export LANGFUSE_SECRET_KEY=...
  export LANGFUSE_HOST=https://<your-langfuse>
  ```
  未配置时导出明确报错并保留本地证据;Langfuse 是展示入口,不是权威证据源。

## 7. 导出、备份与运维(P5)

```bash
# 报告导出(markdown | json | csv | bundle 证据包;CSV 已做公式注入转义)
.venv/bin/python scripts/eval.py export <run-id> --format markdown
.venv/bin/python scripts/eval.py export <run-id> --format csv
.venv/bin/python scripts/eval.py export <run-id> --format bundle   # 含 SHA256SUMS,不含凭据

# 运维健康指标(只读聚合:队列/卡住/未知上游/预算未结/裁判错误/待审时长/磁盘)
.venv/bin/python scripts/eval.py health
curl http://127.0.0.1:7801/api/evals/v1/health

# 告警条件评估(阈值可配,仅列出;默认不发送任何外部通知)
curl http://127.0.0.1:7801/api/evals/v1/alerts

# 观测导出 Outbox(事件副本先落盘;未配置凭据时如实显示未导出)
curl http://127.0.0.1:7801/api/evals/v1/outbox/status
curl -X POST http://127.0.0.1:7801/api/evals/v1/outbox/flush       # 人工重试导出

# 压缩实验配对报告(质量+token+费用,质量退化禁止推广)
curl -X POST http://127.0.0.1:7801/api/evals/v1/compression-report -H 'content-type: application/json' \
  -d '{"baselineRunId":"base","compressedRunId":"comp"}'

# 裁判校准:导入人工独立标注(check 级),报告缺陷召回/误报率;vlm 未校准→质量门禁 inconclusive
curl -X POST http://127.0.0.1:7801/api/evals/v1/calibrations -H 'content-type: application/json' \
  -d '{"judgeModel":"qwen-vl-max-latest","samples":[{"caseId":"c","checkId":"k","autoDefect":true,"humanDefect":true,"split":"calibration_test"}]}'
curl http://127.0.0.1:7801/api/evals/v1/calibrations
```

备份与恢复(恢复前自动校验 SHA256SUMS,并核验素材哈希与 sealed 录制):

```python
from pathlib import Path
from backend.evaluation.backup import create_backup, restore_backup
backup = create_backup(Path("data/evaluation"))                  # → data/evaluation/backups/backup-<ts>
result = restore_backup(backup, Path("/tmp/restored-store"))     # 目标必须为空
assert result["objectProblems"] == [] and result["recordingProblems"] == []
```

保留与撤销(默认 dry-run,删除必须显式执行;被引用对象受保护):

```python
from backend.evaluation.retention import plan_cleanup, execute_cleanup, revoke_artifact
plan = plan_cleanup(Path("data/evaluation"))       # 清单,不删除
execute_cleanup(Path("data/evaluation"), plan)     # 显式执行 + 审计
revoke_artifact(Path("data/evaluation"), "art-xxx", reason="含敏感内容", revoked_by="admin")
```

## 8. 边界与纪律(摘要)

1. Mock/stub 分数仅验证管线,报告与工作台强制标注;不能作为模型质量结论。
2. live 默认预算 0;usage/费用未知保持 null;请求发出后结果未知保留预留、不盲目重试。
3. 严格回放强制禁网:未知请求立即失败(REPLAY_REQUEST_MISMATCH),旁路出口被阻断(NETWORK_FORBIDDEN)。
4. 查看历史 / 离线回放 / 真实复测 / 重新评分是四个不同操作,页面与 API 不混用。
5. 评测数据全部在 `data/evaluation/`(Git 忽略),与线上 `data/` 隔离;主应用保持单进程 JSON 存储。
