# AI 视觉创作平台：工作台、无限画布与 Agent

版本：v0.3 · 更新日期：2026-09-09

状态：产品访谈中的阶段性收敛。用户已明确平台方向、首版聚焦与入口层级；本文其余交互细节是建议，Agent 首条完整用例仍待收敛。本轮只更新产品文档，没有实施界面或 Agent。

本文更新 [v0.2 定位建议稿](./产品定位与PRD-GenCanvas-v0.2.md) 中的定位与信息架构。旧稿的功能验收条目作为参考，不自动全部进入本版范围。

## 1. 已明确的目标与边界

### 用户明确表达

- 项目主要用于加深对图像、视频生成的认识，并形成面向 AIGC 图像/视频 AI 应用全栈岗位的简历项目。
- 产品按平台组织。图片编辑、角色、商品视觉、分镜创作可以属于同一平台，不必作为互斥产品。
- 当前先实现无限画布相关能力，并搭配 Agent。
- 平台需要类似创作工作台的入口；通过「画布」Tab 进入画布模块，创建画布后再进入核心流程。
- 画布左侧为悬浮图标列表，固定包含「本地上传、导入资产、添加画板、添加文字」；画布区域底部居中放置对话输入框，右侧展示对话记录，生成图片也在对话栏中显示。
- 文生图一次生成 4 张图片，分别探索 4 个不同方向，每个方向 1 张。
- 同一次文生图的结果作为一组展示：画布中以提示词为组标题，4 张图片在一个共同容器内横向排列，参照用户提供的截图。
- 文生图、文生视频和抠图流程已经验证。其余能力不能仅因存在代码或接口就视为真实环境验收通过。

### 当前产品定位

**AI 视觉创作平台；首版核心工作区为无限画布与创作 Agent。**

首版体验：从工作台进入画布列表，新建或继续一张画布，在其中通过手动工具和 Agent 生成、加工、组织素材，保存并导出结果。

首批使用者以开发者本人及体验者为主。独立创作者、电商运营等市场画像尚未通过访谈验证，不沿用 v0.2 中的商业用户假设作为已确认事实。

## 2. 产品层级

| 层级 | 职责 | 首版安排 |
| --- | --- | --- |
| 工作台 | 平台统一入口，以 Tab 切换创作模块 | 必须建立入口结构 |
| 模块管理页 | 展示已有内容、创建新内容 | 优先完成画布列表 |
| 内容编辑页 | 打开一个具体文档，持续创作 | 无限画布 + Agent 为核心 |
| 通用能力 | 图像/视频生成、抠图、编辑、素材管理 | 复用已有能力，逐项接入 |
| 场景工作流 | 角色、商品视觉、分镜创作 | 后续基于共享能力扩展，暂不承诺首版全部上线 |

「Tab」在这里指工作台的可见导航标签，不是键盘 Tab 快捷键。

用户侧以「画布」作为首版文档单位，不额外引入必须先创建的项目或文件夹。当前 CanvasDoc 可作为持久化基础；未来多文档项目分组不阻塞首版。

## 3. 入口与页面结构

### 3.1 导航路径

```text
打开应用 → 创作工作台
             ├─ 图片生成 Tab → 图片生成界面
             ├─ 视频生成 Tab → 视频生成界面
             └─ 画布 Tab → 我的画布
                              ├─ 新建画布 → 无限画布 + Agent
                              └─ 点击已有画布 → 恢复该画布 + 对应 Agent 会话

编辑器「返回工作台」→ 我的画布（保留画布 Tab 选中状态）
```

用户已明确「画布」Tab 和新建入口。图片、视频作为并列 Tab 是本稿建议，可复用现有生成流程；工作台默认 Tab 尚未指定。角色、商品、分镜不在首版展示无法使用的空入口。

工作台和编辑器使用两种布局：工作台突出模块选择与内容管理；编辑器突出创作空间，提供明确返回入口。已有画布允许通过稳定地址直接打开，刷新时不会被强制带回工作台或创建新文档。

### 3.2 工作台

- 提供可见的模块 Tab、设置入口和必要的服务状态。
- 切换到画布 Tab 只加载列表，不自动创建文档。
- 进入工作台不要求先配置所有模型；允许用户查看已有作品，准备调用对应能力时再引导配置。
- 已有图片/视频生成入口与画布使用同一批底层能力，具体内容能否跨入口一键加入画布在素材联通阶段验收。

### 3.3 我的画布

- 主操作：「新建画布」。
- 内容卡片：封面、名称、最后更新时间；默认按更新时间倒序。
- 空态：说明画布可用来生成和整理图像/视频素材，展示新建按钮。
- 列表态：点击卡片打开对应画布；重命名作为首版管理能力。
- 加载失败：展示重试，不把网络失败显示成“暂无画布”。
- 删除、复制、文件夹、模板等管理能力暂不作为入口闭环的前置条件。

新建交互建议：点击后创建「未命名画布」，拿到服务端 ID 再进入编辑器，用户可在顶栏重命名。首版不强制填写表单或选模板；避免为开始创作增加额外步骤。

### 3.4 无限画布编辑器

| 区域 | 内容 |
| --- | --- |
| 顶栏 | 返回工作台、画布名称、保存状态、进行中任务、导出 |
| 左侧悬浮工具栏 | 四个图标，依次为本地上传、导入资产、添加画板、添加文字；悬停或键盘聚焦显示名称 |
| 中央画布 | 图片、视频、画板、文字、候选结果、任务占位、错误卡 |
| 画布底部居中输入框 | 输入对话与生成需求、显示本次素材引用、发送；位置相对画布区域居中，不包含右侧对话栏宽度 |
| 右侧对话栏 | 用户消息、Agent 回复、执行步骤，以及生成图片的预览卡片和状态；输入框放在画布底部 |
| 辅助面板 | 导入资产、对象属性按需打开；面板布局不遮挡底部输入框，具体承载方式在线框中示意 |

新画布显示四个图标入口、底部输入框与右侧对话空态。点击新建本身不自动发起模型调用。图片生成需求从底部输入框提交；模型和参数的具体字段仍待确认。

本地上传打开文件选择器；导入资产使用平台已有素材，两者是独立入口。添加画板在本稿按「在当前无限画布文档内新增画板」表达，添加文字新增可编辑的文字对象。画板的默认尺寸、对象归属与裁剪规则，以及文字的格式范围尚待确认。

选择、移动保留为画布基础交互。选中态参照用户提供的截图：仅选中的单张图片显示贴边高亮选框、四角圆形控制点、四边中点胶囊控制点；左上显示图片图标与「图片」标签。控制点的具体缩放约束仍待确认，线框用深灰边框表达高亮。

图片下方展开一整条横向悬浮工具栏，使用白色圆角容器、图标与文字、分隔线。短栏居中于图片，长栏优先限制在画布可视范围内，窄窗口可在栏内横向滚动；不遮挡右侧对话和底部输入框。组内单图选中时其余图片保持原样，四张图片仍属于原生成结果组。左侧四个固定工具图标保持独立。

工具栏按照截图顺序呈现：添加到对话、重新编辑、再次生成、扩图、超清（下拉）、抠图、智能改图、多角度、更多、下载。添加到对话、抠图衔接已有线框流程，下载进入导出规格说明；其余入口仅作为布局占位并标注待确认，不将功能能力及交互细则视为已定义。重新编辑的目标、再次生成的提示词与四图规则、超清规格等需另行明确。

**手动抠图分为蒙版编辑与结果生成两个阶段：选中图片 → 图片工具栏点击「抠图」进入模式 → 识别并显示主体蒙版 → 确认 / 调整蒙版 → 点击蒙版工具栏右下角「抠图」→ 生成中 → 新增一张透明主体图片。**

蒙版叠加在原图的主体区域，背景仍可见；蒙版出现只代表选区准备好，不等于已经生成透明结果。图片下方此时切换为蒙版工具栏，按截图呈现画笔、橡皮、辅助选择、撤销 / 重做与右侧「抠图」主按钮。蒙版出现、编辑或退出均不新增图片；只有显式点击此主按钮才发起结果生成，不使用「应用」作为这一步的按钮名称。

蒙版识别期间禁用结果生成按钮。点击「抠图」后使用本次确认的蒙版，生成期间禁用蒙版编辑和重复提交，按钮显示「生成中…」。返回有效结果后，在当前源图旁边新增一张透明主体图片，并恢复图片对象的操作栏。

抠图结果的默认放置位置为源图右侧，紧邻源图并保持清晰间距。源图保留在原位置；若源图在生成结果组中，新结果紧跟源图插入，同组后续图片顺延，容器扩展。例如：图片 1 → 图片 1 的抠图结果 → 图片 2 → 图片 3 → 图片 4。原来的四张生成图及关联保留，新增结果是抠图派生素材，不计作第五个文生图方向。独立图片同样在源图右侧新增结果；重复抠图后的多结果排列和跨组避让规则待细化。

蒙版识别失败时保留原图，不展示成功蒙版；结果生成失败时保留原图和已有蒙版，允许返回蒙版编辑，返回本身不自动重试。退出蒙版编辑不新增结果。笔刷参数、辅助选择含义、撤销 / 重做细则、未提交蒙版保护，以及识别和生成阶段的取消 / 重试规则待确认。截图中的积分和计费没有纳入当前 PRD。

对话栏默认展开，收起能力沿用此前建议；收起后底部输入框仍保留。手动和 Agent 产生的结果都归属当前画布文档。生成中的占位、失败提示和成功图片出现在对应对话中，已生成的图片以可见预览展示，不只显示一条文字回复。

线框沿用「生成结果落入画布，同时在对话栏显示」的建议；文生图结果在画布上组成一个生成结果组，两处逐图引用同一份资产，避免重复保存。是否先在对话中挑选再加入画布、图片预览的更多操作待确认。

### 3.5 文生图：一轮四个方向

**已确认：一次文生图需求是一个生成任务，同时生成 4 张不同方向的图片，每个方向 1 张。** 画布中的文生图及独立文生图入口遵循同一规则；此数量不自动扩展到抠图、上传、视频生成或其他编辑操作。

- 提交前展示「4 个方向 × 每方向 1 张」的固定说明，本版不提供数量切换。
- 4 个方向围绕同一需求展开，应遵守用户指定的主体、用途及其他约束，在构图、光线、场景或风格等方面形成可说明的区别。具体差异维度为建议，不固定成四种风格模板。
- 同一轮需求对应一个生成结果组：组标题显示本次提示词，组内包含 4 张图片。在画布中，4 张图片放在同一个容器里紧凑横向排列，默认呈现共同的组边界。
- 右侧对话在同一条回复中展示这个结果组的预览；窄栏暂采用组内 2 × 2 缩略图，是同一组的紧凑展示。方向说明与逐图操作的呈现方式待确认，默认不拆成四张带独立标题的卡片。
- 提交后四个占位同时进入「生成中」，共用本轮任务状态；完成后在原位置展示整组四张图片。不展示“一张生成、三张等待”的逐张队列，也不将四张图片表达成四个执行步骤。
- 生成中统一使用深灰背景、高对比加载标识与「生成中…」；失败使用明确的失败图标和文案。线框中仅已生成图片使用图片占位交叉线，未完成任务与图片预览有明确区别。右侧对话同步展示整组状态。
- 组标题下显示「正在生成 · 本轮 4 张 · 同时生成」，不使用逐张完成进度条。成功时以图片替换四个占位，维持本组的大小、顺序及布局。无真实进度数据时仅展示不定进度的加载标识，不编造百分比、排队名次或完成时间。
- 正常完成显示「4/4 已生成」。若整组任务结束后仅返回部分有效结果，作为异常处理：保留返回图片，标记缺失位置与原因，整体显示「部分完成」。该异常不代表逐张提交或依次生成。
- 生成结果组保存提示词、本轮任务及四张子结果的关联，组内每张图片仍是独立资产。刷新查询同一个组的任务并恢复图片顺序，不重复提交生成或重复加入结果。

待确认：方向由系统如何形成、是否允许用户预先编辑方向、如何评估差异是否足够，以及失败方向的补生成方式。组内单图可选中并通过图片下方操作栏抠图；整组移动、拆组等其他操作边界尚未定义。本轮只确认产品规则，不宣称现有接口已经实现四方向生成及结果分组。

## 4. Agent 的建议职责与待定事项

### 4.1 建议的最小职责

- 根据用户显式选中的对象和素材引用理解“这张图”，在界面展示实际引用。
- 调用已接入的生成、抠图、对象摆放等工具，并让用户看到步骤状态。
- 将结果作为新对象放入画布，保留来源与操作记录。
- 将生成图片展示在对应的右侧对话记录中，关联生成任务与资产；输入需求统一从画布底部提交。
- 允许用户定位结果、继续提出修改要求；执行失败时保留已完成结果。

Agent、手动工具共用操作层与任务系统。单次对话任务可包含多个工具步骤；不把模型生成完成直接当作整个用户任务完成。

Agent 只能使用实际接通且通过验收的能力。当前“文生视频已验证”不等于“图生视频可直接开放”；局部重绘也需要按所选服务验证。

### 4.2 尚未确定

- 第一条完整 Agent 用例与验收输出。
- Agent 是否首版支持图像视觉理解，所选模型能接收哪些引用。
- 多步操作的执行范围、允许发起的文生图轮数和中断机制；单轮文生图数量已固定为 4 张。
- 跨会话恢复到何种程度：至少保留历史及步骤结果；是否自动续跑未完成步骤另定，不默认重复调用模型。

此前讨论过的串联用例可按本轮规则调整为：选中人物图，抠出主体，再生成一组四个方向的背景，放到画布供挑选。该用例尚未被用户选定，不自动等同于合成海报或商品成图。

## 5. 入口与文档闭环的验收

| ID | 场景 | 预期结果 |
| --- | --- | --- |
| W01 | 首次打开平台并切换画布 Tab | 展示空态和新建按钮，不产生空文档 |
| W02 | 点击新建画布 | 成功创建一个文档后进入编辑器；双击期间禁用重复提交，防止重复创建 |
| W03 | 创建失败或响应不确定 | 留在列表并说明状态；可安全恢复或重试，不把未创建的文档展示成成功 |
| W04 | 修改名称并添加素材 | 保存成功后，返回列表能看到名称、更新时间及封面或占位封面 |
| W05 | 从列表重新打开 | 恢复正确画布及资产，Agent 历史不得串到其他画布 |
| W06 | 刷新编辑器地址 | 打开同一画布，不新增文档；未知文档显示不存在或返回入口 |
| W07 | 返回时仍有未保存修改 | 先尝试保存；失败保留编辑内容并允许重试或明确放弃，不能显示已保存 |
| W08 | 生成中返回列表后重开 | 任务仍属于原画布；完成后落在正确文档，重复事件不重复插入 |
| W09 | 单纯切换工作台 Tab | 不额外创建文档，不触发生成任务 |
| W10 | 工作台与 Agent 服务不可用 | 已保存画布及本地素材仍可浏览；能力不可用有明确状态 |
| W11 | 打开画布编辑器 | 左侧仅显示四个已确认工具图标，底部输入框相对画布区域居中，右侧为对话栏 |
| W12 | 从底部发送图片生成需求 | 用户消息、任务状态与成功图片在右侧同一段对话中对应展示；生成失败保留原需求和失败提示 |
| W13 | 本地上传 / 导入资产 | 分别进入文件选择和已有资产选择；成功后加入当前文档，取消不添加对象 |
| W14 | 添加画板 / 添加文字 | 在当前文档内新增对应对象，保存并重开可恢复；默认值与编辑细则待补充 |
| W15 | 提交一次文生图需求 | 本轮包含 4 个不同方向、每方向 1 张，遵守同一需求约束；画布中共用提示词标题并在一个组容器内横排，右侧在同一条回复中预览该组；方向说明与差异质量标准待细化 |
| W16 | 四张同时生成、整组成功或异常返回 | 一次提交对应一个任务，四个占位同时显示生成中，画布与对话整组状态一致；不展示逐张排队、四步进度或虚构百分比。完成后在原位显示四张图片，异常返回保留有效结果及缺失位置；刷新不重复提交或插入 |
| W17 | 选中图片并抠图 | 单图显示贴边选框、四角圆点、四边胶囊控制点与图片标签，下方工具栏不遮挡其他区域。进入抠图模式只显示原图上的蒙版；蒙版出现、编辑或退出均不新增结果。必须点击蒙版栏右下角「抠图」才开始生成，生成中禁用编辑与重复提交。成功后在当前源图右侧相邻新增一张透明主体图片；组内后续图片顺延，原四张生成图及关联保留。识别失败保留原图，生成失败保留原图和蒙版 |

Agent 首条用例确认后，增加上下文引用、工具执行、撤销、取消和失败恢复的验收，不能用聊天回答正常替代任务完成验证。

## 6. 实现基础与差距

代码梳理依据：当前 `web/canvas/index.html` 已包含画布、素材库、设置、生成与抠图入口；`src/server.ts` 已有文档列表、创建、读取、保存和删除接口。这些是复用基础，本轮未重新进行浏览器或模型验收。

主要新增工作：

1. 建立工作台导航与画布管理页，接入现有文档服务。
2. 补齐新建、打开、返回、刷新、重命名的导航和保存规则。
3. 整理手动工具与 Agent 共享的操作接口，明确任务与画布的关联。
4. 实现左侧四个图标入口、画板与文字对象、底部输入框、右侧对话及图片结果，并接入工具执行记录和选中对象引用。

角色、商品和分镜作为后续工作流复用素材与操作记录。图片编辑器的精确图层合成、视频拼接、故事自动拆镜等不因平台方向确定而自动加入当前迭代。
