# 块 11：计划语义自检（已确认实施）

目标是在生成预扣、提交之前发现“每步合法，整体跑偏”，不判断画质、不修改计划、不执行工具。继续由主管接收审核原因并重写，只有工人能扣生成积分、调用生成服务或写画布。

## 复用与边界

复用 `core/review/policy.py` 的合法性、类型与 invariants 审核和交付事实，`supervisor/reviewer.py` 的目录适配、`tools/catalog.py` 的价格公式、主管重写计数、现有模型 Provider/路由/凭据解析、Plan 与评测后台。提示词源为下载文档《实现提示词（分块）》“附录 → 计划自检”，仓库中另存带版本及内容哈希的模板。

只改审核与自检模块、主管执行准入、评测和对应测试。不接入新的生成能力、助手派发或前端；保留正在并行开发的资产卡/识别改动。

## 事实摘要

代码从锁定能力表、参数和资产引用图生成摘要：每步工具、依赖、关键参数、输出类型、预估积分；最终交付的模态、数量、尺寸、约分比例、时长与作用对象血缘。中间产物与最终交付分开；摘要保留全部付费步骤，以检查额外付费工作。无法静态确定时标为未知，不能虚构；数据截断必须显式标记，硬要求和用户原话不可静默截断。

## 持久化与准入

候选 Plan（包括被退回的版本）先落库。复用现有审核回执 `Invocation.review.semantic` 保存调用中的状态、唯一键、输入摘要/哈希、模板/路由/策略版本、租约、原始响应、解析结果、降级原因、token 用量和耗时；终态将完整结果写入新追加的 `Plan.self_check.semantic`。保留原有规则结果及兼容字段。Plan 与已保存 Planner 上下文不可变，因此不原地修改候选 Plan 或 Invocation.context；审核结束追加 execute/rejected/obsolete Plan 版本并关联候选。不新增表或迁移，避免与并行 0026 迁移冲突。

流程：候选落库 → 规则审核 → 判断是否触发 → 预登记自检调用 → 释放数据库锁 → 模型调用并先存原始响应 → 重新锁定并验证输入修订/取消状态 → 解析并保存结果 → 准入或退回。自检未结束前，不创建可执行任务、执行准入或预扣流水。候选/拒绝版本不能作为上一个已批准计划。

恢复时复用已保存的响应与结论；已发送且无原始响应的调用记录为结果未知，不盲目重新调用。迟到结果只保留审计，不能放行已过时计划。模型等待期间不能持有 Session/Run 事务锁。

## 策略与降级

含视频（含中间步骤）、长链路/多步骤、派生助手标记或预估积分达到阈值时触发；其余只做既有 invariants 规则。所有阈值、超时、输入输出上限、租约和路由都由配置提供。

附录规定只输出 `{"pass": boolean, "problems": [{"item", "expected", "actual"}]}`。明确不一致才拦截；不确定时通过并记录问题。无有效证据的否决、非法 JSON、超时、服务不可用或调用结果未知都记录为规则降级，不能伪装成模型通过。否决以“期望 X，计划是 Y”进入原有重写流程，共用重写上限。模型调用只计 token，不操作生成积分。

默认关闭；可用 shadow 模式评测但不拦截。enforce 必须配置用户指定的误拦率目标，并提供匹配模板、模型路由、策略和数据集的有效真实评测证据；目标未给出、证据失配或评测降级缺失时不能开启。假模型成绩不得解锁。

## 评测与验证

至少 30 条跑偏计划和 50 条正常计划，覆盖数量、模态、比例/尺寸/时长、对象、漏做、多做付费步骤。输入必须通过合法性与类型检查；另行记录已被 invariants 捕获与模型额外检出的部分。

报告检出率、正常计划误拦率、有效判定覆盖率、不可用/降级数、P50/P95 延迟与模型用量。假接口只验证协议和控制流，不声称真实模型质量；真实模型结果与门槛另行登记。

回归包括：交付摘要、触发边界、JSON 及注入防护、规则降级、空值、调用前后崩溃、原始响应先落库、恢复不重复调用、持锁不等待、插话/取消结果过时、零生成扣费、退回计数和拒绝 Plan 留档。最终运行模块单测、隔离数据库与 HTTP 集成、`npm run verify` 及原有可靠性套件，按 `type(模块): 中文描述.` 分批提交。

## 运行配置与排查

配置统一位于 `core/supervisor/contracts.py::Settings`，环境变量前缀 `AIVERO_SUPERVISOR_`。默认 `SELFCHECK_ENABLED=false`、`SELFCHECK_MODE=off`。明确启用观察时用 `SELFCHECK_ENABLED=true` 与 `SELFCHECK_MODE=shadow`；观察不拦截。`SELFCHECK_ROUTE_ID` 指向现有部署路由；留空复用 Run 冻结的主管路由，显式指定但不存在则记录不可用，不偷偷换模型。

正式拦截还需 `SELFCHECK_MODE=enforce`、用户确定的 `SELFCHECK_MAX_FALSE_BLOCK_RATE`、`SELFCHECK_EXPECTED_DATASET_HASH` 和 `SELFCHECK_EVIDENCE_PATH`。证据必须完整真实且匹配当前路由、模板、数据及有效策略；误拦率必须严格低于目标。缺项或失配只观察，不获得拦截资格。此次不设置用户目标、不打开观察或拦截。

排查读取 Invocation 的 `review.semantic` 和各 Plan 版本 `self_check.semantic`：可见 candidate / terminal 关联、call key、触发原因、路由与策略哈希、原始响应、降级原因及 token 账。`reviewing`、`rejected`、`obsolete` 计划不能被当作已批准计划。生成服务的内容拦截硬规则仍生效；自检模型内容拦截同样停止，不经重写绕过。
