# Agent 权限与密钥隔离讨论

记录日期：2026-09-11。本文记录讨论共识与待定方案，不代表功能已实现或通过安全审计。

## 权限边界

- 应用内创作 Agent 与有文件、命令工具的开发 Agent 是不同信任主体。
- 创作 Agent 仅开放生成、查询、取消等必要业务工具，不提供任意文件读写、终端、任意 SQL 或代码执行。
- 上下文只包含当前任务需要的需求、明确引用的素材、蒙版和相关历史，不包含密钥。
- 用户确认与后端鉴权是两道独立门禁。高风险操作的确认绑定具体对象、操作、数量及有效期，由后端记录和验证，不能接受模型声称已确认。
- 后端从可信会话获取身份，逐次检查项目成员权限、素材与任务归属、本次授权；下载、缩略图、历史及事件订阅同样需要隔离。
- 默认不向 Agent 开放永久删除、清空项目或修改权限。编辑创建新版本；未来若开放删除，优先回收站，并限制整个任务累计操作数量。
- 请求去重、文档 ID 和素材 ID 不等于访问授权。多用户隔离尚需专门实现与验证。

## 密钥现状

本次代码检查发现：设置提交的 Key 会写入本地 config.json；配置查询接口返回脱敏状态；Provider 在服务端请求时添加鉴权头。开发 Agent 可读取项目文件，因此当前没有对开发 Agent 隔离密钥。生成链路测试不等于密钥安全审计。

## 正在讨论的本地方案

用户希望保留设置中的 Key 输入，将凭据保存在用户本地，由受控程序读取，避免创作 Agent 访问本地文件。

### 已确认的硬性约束

- Key 只能持久保存在用户本机，不得上传应用云端服务器、同步服务、遥测或日志平台。
- 厂商调用必须由用户本机的可信组件发起，不能将 Key 交给应用云端后端代调。
- 调用百炼等云端 API 时，Key 仍须通过 HTTPS 发给对应厂商的鉴权端点；这与上传给应用服务器保存不同。若要求 Key 完全不离开本机，则不能使用该类 API Key 鉴权的云端服务。
- 云端部署时，现有将 Key POST 到 /api/config 并写入服务器 config.json 的流程不符合约束，不能直接沿用。即使当前运行在 localhost，也不能将该实现视为已完成本地专用凭据方案。
- 纯网页方案需要可信本地伴随服务或桌面壳实现本机凭据保存与厂商调用。应用云端只能接收业务需要且获授权的数据，不接收 Key。

- 设置界面直接将凭据交给本地凭据服务，不经 Agent 对话或工具参数流转。
- 候选存储为操作系统凭据库，而非项目 config.json、前端 localStorage 或普通 .env。具体选型待定。
- 读取凭据的程序应同时完成厂商请求，只返回结果或脱敏错误；不能把 Key 打印到 stdout、返回给 Agent 或写入日志。
- 创作 Agent 只提交结构化生成参数。凭据服务不接受任意文件路径、命令或请求目的地址；目标厂商固定并校验，防止携带凭据向任意地址发送请求。
- 本地服务仍需调用方认证、请求范围和额度控制；仅绑定 localhost 不构成完整授权机制。
- 同一用户权限下的脚本、独立进程或加密文件，不自动构成对开发 Agent 的安全边界。强隔离还需操作系统权限、沙箱或独立可信环境，限制凭据读取、服务代码修改及调试访问。
- 本地浏览器页面不能直接读取系统凭据库。纯网页若使用本地凭据，需要另行部署可信本地服务或桌面壳；云端部署则不能假定服务器上的文件是用户本地文件。

## 后续待定

1. 产品部署形态：本地桌面/本地服务，或多人云端网页。
2. 保护范围：隔离创作 Agent，还是同时隔离开发 Agent 与其他本机进程。
3. 凭据存储、服务身份与访问授权实现，及已有明文 Key 的迁移方式。

本次仅记录讨论，未迁移密钥或改动权限实现。

## 后续决策：开发与生产分离

用户后续选择开发时使用本机开发者 Key，上线时由平台提供服务端 Key，普通用户不再填写 Key。此前用户 BYOK 本地伴随服务方案作为历史备选，不再是当前上线方向。设置入口和配置读写、连接测试接口仅在显式 development 环境开放；生产凭据通过部署配置提供。此变更不等于完成密钥存储迁移或多用户鉴权。
