## 1. 目标与参考边界

在现有 FastAPI + 原生画布架构上补齐三条能力线，产品形态参考即梦（jimeng.jianying.com）：

1. **图生图**：带参考图的图片生成。单图生成通路已存在（`referenceAssetIds`），本方案补齐参考强度语义、四方向组图生图和输入卡入口。
2. **文生视频**：文字描述生成短视频。ComfyUI 路径已实现，云端路径未接入；本方案补齐云端异步 Provider、视频资产元数据与输入卡视频模式。
3. **时间线**：把画布上生成的视频片段按分镜顺序编排、预览成片并导出。当前完全没有对应实现，是三条线中体量最大的新功能。

生成质量与可用性以外部大模型为准（用户已确认方向）；ComfyUI 与 Mock 只承担本地流程联调，本地实测结论不外推为云端模型质量结论。

只参考即梦的功能形态与交互组织，不使用其媒体素材，不复制其社区、积分、会员、数字人、对口型等能力宣称，不在未验收前把界面文案写成已具备的能力。

## 3. 总体原则

1. **不新建队列、不换存储**。三条线全部复用现有 `Provider` 接口、`Jobs` FIFO 队列、`requestId` 幂等、SSE 事件与文档 JSON 模型。时间线导出是本地确定性处理（同抠图合成的定位），也不引入第二套执行器。
2. **能力门控先行**。每个新能力先落 `GET /api/generation-capabilities`（支持/不支持 + 原因 + 可选值），前端只渲染能力返回的选项；不支持的组合禁用并说明，不做静默降级。
3. **供应商参数不猜**。适配器的参数形状（模型名、尺寸档、时长档、强度参数）先做能力实验并记录证据，再写进代码与能力契约；实验不通的参数不透传，也不在前端保留假选项。
4. **付费语义**。沿用既有约定：提交结果未知只查询不重提；重启不自动重发任务；「重试/重新生成」必须由用户显式触发并提示会产生新调用。
5. **前端新模块一律 TypeScript**（AGENTS.md 约束）。时间线全部新建 `.ts` 模块并纳入 `tsconfig.web.json` 与 `npm run build:web`；触碰的既有 `.js` 文件在同任务内迁移或书面说明原因。
6. **云端大模型是主路径，接入必须可重复**。每个新厂商/新模型走同一套四步流程：能力实验（真实小样 + 记录证据）→ 能力契约（`generation-capabilities` 写实档位与限制）→ 适配器（实现 `Provider` 接口，注册进 `build_provider`）→ 验收（真实调用 + 兼容测试）。禁止只改配置或模型名就宣称支持；适配细节优先收敛到 [统一模型网关方案](./统一模型网关方案.md) 的网关后面，应用侧只面向网关协议与受限令牌。

## 4. 图生图

### 4.1 交互（参考即梦）

- 输入卡（`composer`）增加参考图挂载：点「+」上传、从资产库选择或从画布「添加到对话」图片；参考图以可移除缩略图显示，不随画布选择偷偷替换（沿用 Agent 引用语义）。
- 模式为 `generate` 且挂了参考图时，提交即图生图；提示保留参考程度控件（低/中/高三档，映射 `referenceWeight`），当前后端不支持调节时控件禁用并注明「当前模型不支持参考强度」。
- 画布右键「以图生图」与节点面板的参考图通路维持现状；本轮只统一参数语义，不重复做第二套表单。

### 4.2 请求契约扩展

`POST /api/generate` 与 `POST /api/generate/group` 的 body 增加可选字段：

```json
{"referenceAssetIds": ["<uuid>"], "referenceWeight": "medium"}
```

- `referenceWeight` 枚举 `low | medium | high`，缺省 `medium`。旧的纯数值/缺失请求按缺省处理，老客户端不受影响。
- `GenParams`（`backend/models.py`）新增该字段并纳入 `requestHash` 指纹——同 `requestId` 改强度即 `409`，与现有「同一请求标识不能更改生成参数」一致。
- 校验沿用现状：参考图 ≤1 张、≤8MB、`kind=image`；参考图与 `initImage` data URL 互斥。

### 4.3 Provider 适配矩阵

参考强度在不同后端的真实语义完全不同，不能假装同一个数值可以透传：

| 后端 / 模型 | 参考图传递 | 强度语义 | 处置 |
| --- | --- | --- | --- |
| aliyun `qwen-image-edit-plus` | messages content `{"image": dataURL}`（已实现） | 官方协议未提供经过验证的强度数值参数 | 首版不透传强度；`referenceWeightAdjustable=false`。模型语义是**指令编辑**，与即梦「参考生成新图」不完全一致：同主体新图、风格迁移等目标需能力实验后再决定是否开放，实验前 UI 文案写「编辑此图」不写「参考生成」 |
| siliconflow `FLUX.1-Kontext-dev` | `image` dataURL（已实现） | 无强度参数 | 同上，不透传 |
| comfyui | LoadImage + VAEEncode（已实现） | `denoise` 即强度（低=0.3–0.45，中=0.55–0.7，高=0.8–0.95，具体档位实验后固定） | 档位映射到 `denoise`；`capabilities.image.referenceWeightAdjustable=true` |
| mock | 参考图与生成图按 `denoise` 混合（`Image.blend`） | `denoise` 即强度，天然演示档位效果 | 档位映射到 `denoise`；仅用于流程测试，不作为强度语义的验收依据 |
| 后续候选（均待实验） | 火山引擎 Seedream（原生多参考图，对应即梦 4.0 多图组合形态）、OpenAI `gpt-image-1`（edits 接口支持图 + 蒙版） | 协议均未在仓库验证 | 按 §3 原则 6 的四步流程补齐证据后才进入本矩阵与能力契约 |

首版结束条件：云端强度档位要么有实验证据并接入，要么在能力契约中明确 `false` 并在 UI 禁用；不允许出现调了没反应的滑杆。

### 4.4 四方向组图生图

`/api/generate/group` 扩展可选 `referenceAssetIds`：

1. 服务端读取并校验参考图（同 §4.2），为四个方向任务各构建同一 `InitImage`；组内共享一次参考图解码，不重复读盘。
2. `directions()` 规划保持确定性四方向；有参考图时方向轴仍为构图/光线/场景/特写，硬约束（风格、禁令）追加在每个方向的提示词尾部，语义是「围绕同一张图做四种表达变化」。规划器是否需要为编辑语义改写方向句式，列入 §4.3 的能力实验。
3. 前端 `submitGroupGeneration`（`web/canvas/flows/group-generate.js`）透传参考图字段；四个占位的组卡标注「图生图」来源。迁移注记：该文件为 `.js`，同任务内迁移为 `.ts`（其依赖 `commands.js`/`placement.js` 的类型以 `node-model.ts` 既有 `CanvasObj` 契约为准）。

### 4.5 兼容与验收

- 老请求体（无新字段）行为逐字节不变：`tests/` 补「旧 body → 同一上游请求参数」断言；`requestHash` 对新旧 body 分别计算并断言不同。
- 验收用例：单图生图（comfyui 档位可感知、云端明确不支持强度）、组图生图四方向共享参考图、参考图被删后提交返回明确错误、`referenceWeight` 改动触发 `409`。

## 5. 文生视频

### 5.1 入口与门控

- 输入卡模式下拉增加第三项「生成视频」：选中后输入卡显示时长（能力返回的 `durations`）与比例（`ratios`）选择，提交 `kind=video` 的**单条**任务（不进四方向组——视频的「四方向」语义、费用与时长都与图片不同，本方案不做组视频）。
- `generation-capabilities` 是唯一开关：`video.supported=false` 时模式项显示但禁用，副文案用能力返回的 `reason`（现状文案已具备，云端接入后自动翻转为可用）。
- 画布节点面板与右键「生成视频」保留，与输入卡共用同一套 `/api/generate` 参数与占位节点状态机（`node-model.ts` 的 `NodeRun` 已覆盖 submitting/queued/running/failed/uncertain）。

### 5.2 ComfyUI 路径（本地联调后备，现状维持）

`comfyui.py` + `workflows.py` 已实现 LTXV（32 像素对齐、8n+1 帧长）与 Wan 2.1（16 像素对齐、4n 帧长、单/双 UNet），首帧参考图即图生视频。按修订方向，该路径定位为无外网/无额度时的本地联调后备，不承担质量验收。本方案不改其工作流，只补两件事：能力契约中把各后端实际可用的尺寸/时长档位写实（当前 `capabilities.py` 的 `resolutions=[512,768]` 与 LTXV/Wan 的对齐约束并不严格一致，需按工作流实测修正）；`videoBackend` 自动探测失败时的报错文案指向 `videoModel` 配置。

### 5.3 云端大模型适配层（新增，多厂商）

视频生成的主路径是接入云端大模型。为避免「每接一家重写一遍任务逻辑」，适配层按厂商拆成薄适配 + 共厚内核：`backend/providers/cloud.py` 的 video 分支持有统一的异步任务内核（创建/查询/取消/下载四步 + 轮询节奏 + 状态映射），各厂商只实现这四个方法并声明档位；能力契约逐厂商下发支持的模型、尺寸、时长。厂商接入一律走 §3 原则 6 的四步流程，协议形状以官方文档与实测为准。

| 厂商 / 模型（候选） | 协议形态 | 现状与备注 |
| --- | --- | --- |
| 阿里云百炼 通义万相（wanx2.1-t2v-turbo/plus、wan2.2 系列） | DashScope 异步任务（创建返回 `task_id`，轮询 `/tasks/{id}`） | **首版目标厂商**：图像通路已接、账号与 Key 管理可复用；`videoApiKey` 已在配置与设置界面预留 |
| 火山引擎 Seedance（即梦同源视频模型） | 火山方舟 API，任务形态待验证 | 与产品参考（即梦）同源，优先级建议第二位；协议未在仓库验证 |
| 智谱 CogVideoX | open.bigmodel.cn，视频为异步任务 | 图像厂商已在 `cloudVendor` 列表内，Key 可复用；视频协议待验证 |
| 硅基流动 | 视频 API，模型与档位待验证 | 图像通路已接；视频协议待验证 |

前四步之后的第二个厂商接入同时是对「薄适配 + 共厚内核」抽象的验证：若第二家需要改内核才能接上，先修内核再接，不为单厂商在内核里开特例。若 [统一模型网关方案](./统一模型网关方案.md) 落地，厂商适配整体迁到网关侧，应用内核只面向网关的创建/查询/取消协议。

以百炼为例的 DashScope 异步协议形状（**以官方文档与实测为准，以下为实验前置假设**）：

```text
创建:  POST {base}/services/aigc/video-generation/video-synthesis
       header: Authorization Bearer <videoApiKey>, X-DashScope-Async: enable
       body:   {model, input:{prompt, negative_prompt?}, parameters:{size, duration?}}
       响应:   output.task_id
轮询:  GET  {base}/tasks/{task_id}
       响应:   output.task_status ∈ PENDING|RUNNING|SUCCEEDED|FAILED|CANCELED|UNKNOWN
               SUCCEEDED 时 output.video_url
下载:  GET video_url → 落盘 mp4
```

实现要点：

1. 对任务队列仍然只暴露 `Provider.generate(params, seed, progress, image, mask)` 一个签名；内部由共享异步内核驱动，各厂商薄适配只实现「创建任务 / 查询任务 / 取消任务 / 下载产物」四个方法。进度映射统一在内核：`PENDING → progress(0.05,"排队中")`，`RUNNING → progress(0.3,"生成中")`，下载阶段 `progress(0.85,"下载视频")`。不伪造逐帧百分比。
2. 各厂商的 `videoModel` 与尺寸/时长档位来自能力实验后的硬编码白名单（逐厂商进 `capabilities.py`），请求前显式校验，不匹配报 `ValueError`（中文说明支持档位），不做静默取整——`durationSec=4` 若厂商只支持 5s，必须报错而不是悄悄生成 5s。
3. 参数与 `seed`：厂商无 seed 语义时不透传，能力契约标注；提示词中译英沿用现有 `cloudTextModel` 通路（视频提示词通常更长，翻译上限与超时需单独验证）。
4. 首版只做 t2v；i2v（`image` 存在时）对云端明确报「暂不支持」，待实验后单独开启。

### 5.4 任务语义：取消、超时、重启

| 场景 | 行为 |
| --- | --- |
| 取消（queued 未派发） | 现状不变：直接 `cancelled` |
| 取消（已创建上游任务） | 调用厂商取消接口（协议含 `task_status` CANCELED，需实测）；仅当上游明确确认才提示「已停止」，否则「停止请求已发出，结果未知」；已产生费用不宣称退还 |
| 超时（`videoTimeoutMin`，默认 60min） | `generate` 抛超时，任务 `failed("生成超时")`；上游任务可能仍在跑，提示文案注明「上游可能仍在执行，请勿立即重复提交」 |
| 重启 | 现状把 queued/running 一律标 `failed("服务已重启,任务中断")`。对视频任务升级：**上游 `task_id` 创建成功后立即写入 job 记录并落盘**（`jobs.json` flush），重启后带 `externalTaskId` 的任务标记为 `unknown` 而非 `failed`；`GET /api/jobs/{id}` 返回 unknown 与「查询上游」入口，`POST /api/jobs/{id}/reconcile` 只查询上游并按结果收尾（SUCCEEDED→下载落盘；FAILED→failed；仍在跑→继续等待），**绝不自动重新提交**。`unknown` 是新状态枚举，前端 reducer 需同步并配兼容测试（旧 jobs.json 无此状态必须照常加载） |
| 容量 | 云端视频任务与图片任务共享 capacity=2 即可（首版不拆分池），队列满仍 429 |

### 5.5 视频资产元数据与海报

- 首版**前端提取**：视频落位节点时由 `<video>` 读取 `duration`/`videoWidth`/`videoHeight`，并捕获一帧绘入 canvas 生成海报 JPEG，`POST /api/assets/{id}/metadata`（新增，body：`{durationMs,width,height}` + 二进制海报，或两步：metadata JSON + `POST /api/assets/{id}/poster`）。后端写回 `Assets` meta 并生成 `posterAssetId` 引用。提取失败不阻塞落位，资产标「元数据缺失」，时间线拒绝收编无时长的素材并说明。
- 备选（列为后续）：后端引入 ffprobe 锁版本统一提取，替换前端方案；本轮不安装 ffmpeg 依赖到运行镜像，避免与「Docker 运行阶段只有 Python」的部署假设冲突——若导出功能落地（§6.5），ffprobe/ffmpeg 一并锁定版本。
- 画布视频对象播放、下载维持现状（原生 `<video controls>` 弹层、Range）；海报帧仅用于时间线与列表展示，不替代原文件。

### 5.6 费用与安全

- `videoApiKey` 与图片 Key 同级脱敏（`public_config` 已处理 masked）；错误信息沿用现有 key 脱敏替换。
- 提交视频任务前在输入卡副文案标注「将调用付费视频模型」；不自动重试、不做质量重抽；免费额度用尽后的计费防护不在应用侧承诺（与 [百炼生图接入](./百炼生图接入.md) §3 立场一致，建议用户在厂商控制台开启额度停用）。

### 5.7 验收

- 真实厂商小样：1024×720 档单条 5s 视频，任务 completed、文件可播放、历史可恢复、控制台可见调用（Mock 与桩测试不算）。
- fake 上游夹具覆盖：PENDING 超时、RUNNING 中 FAILED、SUCCEEDED 但下载 404、轮询中服务重启→重启后 unknown→reconcile 收尾、取消竞态（取消与 SUCCEEDED 同时到达时以任务已终态为准，不重复落盘）。
- 前端：输入卡视频模式占位节点按 `NodeRun` 状态机走完刷新恢复；能力禁用时三个入口（输入卡/节点面板/右键）口径一致。

## 6. 时间线

### 6.1 范围

参考即梦「故事/分镜」的时间轨道管理与成片预览。首版语义是**顺序序列**（分镜依次首尾相接），不是自由多轨 NLE：

| 首版做 | 首版不做（后置） |
| --- | --- |
| 单视频轨顺序序列（≤50 个片段）；片段来自视频资产：上传视频或画布上的真实 mp4/webm 素材 | 多轨叠画、画中画、自由摆放与空隙 |
| 裁剪（in/out）、调序、删除片段 | 关键帧、变速、倒放 |
| 顺序预览播放（播放头、标尺、播放/暂停） | 字幕、贴纸、配音、音乐轨（数据结构预留 `kind: 'audio'`） |
| 导出成片 mp4（ffmpeg，确定性处理，不经大模型） | 转场（首版仅硬切；dissolve 后置）、调色 |
|  | 分镜自动规划（文本大模型把一段需求拆成 N 个分镜提示词与时长，复用 `planning.py` 的受限规划 + 服务端校验模式；属外部大模型接入，走 §3 原则 6 流程） |

入口与布局约束：**左栏四项（上传/导入资产/画板/文字）是不可悄悄改变的约束**，时间线入口放顶栏「时间线」切换按钮（与现有主题切换同级），不做左栏第五项。视频对象工具栏增加「加入时间线」属于新能力，与图片操作栏「添加到对话/抠图/下载」约束不冲突，但需 PRD 层面确认（§9）。

### 6.2 数据模型与持久化

前端类型（新模块 `web/canvas/timeline/`，全 `.ts`）：

```ts
export type TimelineClip = {
  id: string
  assetId: string          // kind=video 且有元数据的资产
  inMs: number             // 源内裁剪起点 ≥0
  outMs: number            // 源内裁剪终点 > inMs，≤ 素材时长
}
export type TimelineTrack = { id: string; kind: 'video'; clipIds: string[] }  // clipIds 顺序即时序
export type Timeline = {
  id: string
  fps: 24 | 30
  tracks: TimelineTrack[]       // 首版恰好 1 条
  clips: Record<string, TimelineClip>
}
```

- **顺序序列语义**：时序由 `clipIds` 顺序与各片段裁剪时长派生（第 n 个片段的 start = 前 n 个时长之和），不持久化 `startMs`，消除「顺序与坐标双真相」。
- 持久化到文档：`document.sequence = Timeline | undefined`，随现有 `POST /api/documents/{id}` 全量保存走 `revision`/`baseRevision` 冲突机制。校验规则（`backend/storage.py` Documents.save）：clips ≤50、tracks 恰好 1、`clipIds` 无重复、in/out 数值有限且 0 ≤ in < out、JSON 序列化 ≤8KB、`assetId` 形状合法（资产是否存在由读取端容错，保存不阻塞——与服务端不回读大资产的现状一致）。
- **兼容语义（重要）**：现有 `groups`/`chat` 是「提交里没有该键即丢弃」的条件覆盖。`sequence` 必须采用相反的 **absent-protect**：提交不含 `sequence` 键时保留服务端现值。原因：旧前端与脚本不认识该字段，全量覆写会静默清空用户时间线。这是对 Documents.save 行为的扩展，需同时补 `groups`/`chat`/`sequence` 三者缺席行为的回归测试，防止「修了 sequence 破坏 groups」。
- 撤销：时间线编辑命令（加片/裁剪/调序/删除）接入 DocStore 现有 command undo 栈（纯命令 + 逆命令），与画布对象命令同一撤销历史；不引入第二套 undo。
- 命中大小上限（文档 5MB）时保存失败走现有错误链路提示，时间线 JSON 本身 ≤8KB 不是瓶颈，瓶颈仍来自 objects。

### 6.3 编辑器交互（底部停靠面板）

- 顶栏「时间线」切换底部停靠面板（建议高度 200–260px，可收起）。收起状态、缩放比例、播放头位置属于 transient UI，不进文档、不增 revision。
- 面板结构：左侧片段列表（缩略图 + 时长），右侧轨道区（时间标尺、片段块、播放头）。片段块支持：拖动换序、拖两端手柄裁剪（吸附到 0.1s）、双击回弹到整段、Del 删除。「+」从资产库选视频，画布视频对象工具栏「加入时间线」同效。
- 片段入库链路：生成结果只存在于 history（`src=/images/…`），「加入时间线」时对无 `assetId` 的视频节点复用 `asset-util.ts` 的 `ensureAsset` 思路做视频版扩展（下载原图 → `POST /api/assets?kind=video`），拿到稳定 `assetId` 与元数据后再入轨；Mock 后端的「视频」是 webp 动图，服务端本就拒绝以 `kind=video` 入库，时间线拒收并提示「当前后端的视频产物不支持编排」。
- 与现有布局规则的交叠：面板打开时，画布底部回落输入框与底部停靠工具栏改停靠在时间线面板上缘（PRD §4.1 的安全矩形把时间线面板并入排除区）；「时间线」面板与蒙版/重绘工具栏互斥时后者优先（正在抠图不被打断）。
- 键盘：空格播放/暂停仅在面板聚焦时生效；IME 组合期间不触发任何时间线快捷键（沿用画布现有 IME 约定）。
- 空时间线面板显示引导文案与「从资产库添加」入口，不自动收编画布上的全部视频。

### 6.4 播放引擎

顺序序列的预览用「视频元素池 + 顺序接力」，不做逐帧合成：

1. 常驻 ≤2 个 `HTMLVideoElement`：当前片段 + 下一片段预加载（`preload="auto"`，seek 到 in 点）。
2. `requestAnimationFrame` 驱动播放头：以当前片段 `currentTime` 累计序列时间；片段边界切换在 rAF 中检测，预加载元素 `play()` 后旧元素 `pause()` 并归还池。
3. seek 校正：播放头拖动定位到目标片段并 `currentTime = inMs + offset`；`seeked` 完成前显示缓冲态，不叠加播放。
4. 自动播放策略：首次播放必须在用户手势内调用 `play()`（浏览器策略），失败时显示播放按钮重试，不静默失败。
5. 离开面板/切换文档/`pagehide` 一律暂停并释放 src，播放器键盘事件不外溢到画布（沿用视频弹层现状约定）。
6. 音频：首版生成的视频片段通常无音轨，预览不额外配乐；素材自带音轨随片段播放。

### 6.5 成片导出

- 能力探测：`GET /api/health` 或新增 `GET /api/timeline/capabilities` 返回 `exportSupported`（检测 ffmpeg 可执行 + 版本）。不支持时导出按钮禁用并写明「服务端未安装 ffmpeg」，不提供假导出。
- 接口：`POST /api/timeline/export`，body `{documentId, requestId, sequence}`；幂等与 `/api/generate` 同模式（`requestId` + body hash + cancelled 登记），返回 202 + jobId，复用现有队列与 SSE 事件。`requestId` 幂等保证双击/重试只产出一条导出任务。
- 执行：`Jobs` 增加 origin 分支——job 记录 `origin: 'generation' | 'timeline_export'`；导出任务不经 Provider，runner 调 `backend/timeline.py` 的确定性导出函数（新模块，定位同 `cutout.py` 的合成）。ffmpeg 命令形状（首版）：

```text
每片段: -ss <inMs> -t <dur> -i <asset>
滤镜:   [i:v]scale=W:H:force_original_aspect_ratio=decrease,
        pad=W:H:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=<fps>[vi];
        [v0][v1]...concat=n=N:v=1:a=0[outv]
输出:   -map [outv] -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p -an out.mp4
```

- 统一目标分辨率取各片段众数分辨率的 16 对齐值（首版简单化：以第一个片段的分辨率为准，其余 letterbox），导出前用 ffprobe 校验素材时长 ≥ outMs，防止裁剪越界产生黑尾。首版输出无音轨（`-an`），音轨混流后置。
- 取消：导出是可安全终止的子进程，`jobs.cancel` 对导出任务 `terminate()` 子进程并等其退出后才释放容量槽（对齐「线程实际完成前不释放槽位」的既有约定）；产物临时文件回收。
- 产物登记：导出结果写入 `Assets`（kind=video，含前端补传的元数据路径不适用——导出后由**后端** ffprobe 直接写 duration/width/height，这要求 ffmpeg 落地时一并接 ffprobe 元数据）+ `History` 记录（`origin=timeline_export`，params 存片段摘要）。前端 toast「导出完成」，资产入库，**显式「加入画布」**落位（同抠图 needs_placement 语义，不自动插图、不复活已删对象）。
- 进度：首版按片段计数发布粗粒度进度（n/N），不解析 ffmpeg 逐帧进度；UI 不显示百分比假精度。

### 6.6 保存、恢复与冲突

- 时间线编辑即文档编辑：走 1s 防抖 autosave 与 revision ACK；「已保存」判定与画布一致（最新本地 revision 命令全部 ACK）。
- 刷新恢复：文档 JSON 的 `sequence` 随 snapshot 回来即可重建面板；无 sequence 时面板为空态。
- 双标签：A 标签改时间线、B 标签保存 → `baseRevision` 冲突 409 → 沿用现有 Conflict 流程（保留本地草稿、拉新快照、明确展示），不静默覆盖。
- 删除被时间线引用的资产：时间线保留 clip 并标记「素材缺失」，播放跳过、导出前置校验失败并指名缺失片段；不做静默剔除。

### 6.7 验收

- 编辑：50 片段压测下滑动/拖动不卡顿（目标：交互 P95 <100ms，标注为待测目标）；裁剪与调序撤销/重做正确。
- 播放：任意序列顺序正确；片段边界无黑帧（硬切目标，实测记录）；刷新后播放头位置不要求恢复（transient），序列必须恢复。
- 导出：输出时长 = Σ(outMs−inMs)（±1 帧容差）；分辨率统一且内容无拉伸（允许 letterbox）；导出中途取消不残留半成品资产；重复 requestId 只产出一个成品。
- 兼容：旧文档（无 sequence）加载/保存无损；旧客户端保存不清空 sequence（absent-protect 回归）；jobs.json 旧记录无 origin 字段照常加载。
- 迁移：无（sequence 是新字段，不需要历史数据迁移）。

## 9. 风险与待负责人确认项

1. **时间线入口位置**：顶栏「时间线」按钮不改左栏四项约束——请确认；若坚持入口在左栏，则属于对 PRD §1.2 约束 2 的显式修订，需同步 PRD 与交互文档。

4. **ffmpeg 依赖**：导出功能要求运行环境提供 ffmpeg/ffprobe 并锁版本，Docker 运行镜像需加入该依赖——这是部署假设的变更，请确认接受后再排 V4。
5. **语义风险**：云端图生图当前通路是「指令编辑」模型，与即梦「参考生成」的语义差异可能导致用户预期偏差；能力实验结论出来前，入口文案按「编辑此图」表述。

主要工程风险：视频长任务的重启/取消/计费边界（§5.4 的 unknown 语义是本方案对现有任务模型唯一的状态机扩展，务必与兼容测试同批落地）；absent-protect 若遗漏回归测试，时间线会被旧路径静默清空；播放引擎的片段边界体验依赖浏览器视频解码时序，需真机实测而非仅凭桌面 Chrome 结论。
