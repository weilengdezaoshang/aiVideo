# 画布 Agent 角色与背景参考生成设计

状态：待确认的补充设计。最终主方案为[画布 Agent 详细设计](./技术方案-画布Agent详细设计-v1.0.md)。本方案补充用户提供角色图、背景图后发起图片生成的流程，沿用预览、正式化和文档写入授权规则。

## 1 支持的输入组合

| 输入                     | 生成目标                                     | 需要说明的条件                                       |
| ------------------------ | -------------------------------------------- | ---------------------------------------------------- |
| 角色图与文字要求         | 角色出现在新的场景中，或改变动作、服装与构图 | 明确保留哪些角色特征、允许改变哪些特征               |
| 背景图与文字要求         | 根据场景生成画面，或向场景增加新内容         | 区分参考场景风格与保留已有背景                       |
| 角色图、背景图与文字要求 | 指定角色出现在指定场景中                     | 分别传递角色和背景，明确位置、比例、动作与融合要求   |
| 多张同一角色的参考图     | 提供不同视角或细节，以辅助身份一致性         | 用户明确这些图片对应同一角色；模型支持相应参考数量   |
| 多个角色与背景图         | 生成多人互动或分镜画面                       | 每个角色独立命名，绑定对应参考与动作；能力单独验证   |
| 上述输入与构图草图       | 同时约束角色、场景和布局                     | 验证角色、背景、构图的组合能力，不能仅凭图片数量判断 |

图片生成是本次补充的主要范围。需要视频时，先生成并确认首帧，再进入主方案的逐段视频流程；不能绕过首帧确认和模型延续能力检查。

## 2 引用角色与约束

角色图沿用 subject 引用角色，在类型化输入中标记 subjectType 为 character。增加 background 引用角色，表示背景来源。composition 继续只表示构图参考，editTarget 表示待修改的整图。背景图不自动兼作风格图、构图图或待修改整图。

每个角色建立 entityId 和显示名称。同一角色的多张图片明确关联到同一 entityId，多个角色使用不同 entityId。无法判断多张图对应一个角色还是多个角色时，先补充输入。

```ts
type CharacterBackgroundInput = {
  taskKind: 'generateImage'
  characters: {
    entityId: string
    name: string
    subjectType: 'character'
    referenceIds: string[]
    preserve: ('identity' | 'clothing' | 'accessories')[]
    requestedAction?: string
    requestedClothing?: string
  }[]
  background?: {
    referenceId: string
    mode: 'reference' | 'preserve'
    preserve: ('layout' | 'landmarks' | 'lighting' | 'pixelsOutsideEditRegion')[]
  }
  compositionReferenceId?: string
  prompt: string
  outputSize: { width: number; height: number }
}
```

referenceIds 解析为已授权访问的不可变素材和 ReferenceBinding。实体关系、输出尺寸与保留要求进入 InputSnapshot、Constraint 和 recipeHash。枚举表示要求，不表示所有模型都支持这些能力。

角色身份、服装和配饰分别检查。用户要求换装时，不能同时无条件保留原服装。改变姿势需要生成新角色像素；直接复用已有角色像素只能保持已有外观和姿势。存在冲突时先说明并调整要求，不能自行降低约束。

background.mode 为 reference 时，背景提供场景特征，允许生成新的布局和像素；为 preserve 时，按具体约束保留原场景。保留场景地标属于语义约束，保留编辑区外像素属于程序硬约束，不能用同一承诺混淆两者。

## 3 用户操作

用户可以上传图片，或引用画布上的已有素材。在输入框中分别显示角色图和背景图的名称、缩略图、角色标记与移除按钮。上传到独立素材存储不自动向文档新增对象。

Agent 先解析明确要求。用户说“让角色 A 出现在这张背景里”，且角色 A 与背景引用已经确定时，可以准备一次预览；引用来源、角色归属或需要保留的范围不清楚时，先补充输入。

用户仅选中图片不会自动加入生成引用。用户明确指代选中对象时，按对应查询快照解析并显示具名引用；不能将后续选择变化静默替换为新参考。此能力依赖尚待合并的[只读查询工具方案](./技术方案-画布Agent只读查询工具-v1.0.md)，引用框显式添加不依赖该查询能力。

生成前展示本轮预览与必要检查的费用范围。产物先保存在独立候选区域。正式结果准备完成后，再展示具体文档变更并申请写入权限；生成授权不允许修改原角色图、原背景图或现有文档对象。

## 4 工具与配方

新增 prepare_reference_generation 作为不触发媒体生成的任务准备工具。它解析角色、背景、构图与约束，查询能力并返回确定任务配方、缺失输入或能力缺口。预览继续通过 generate_image_preview 和现有 ExecutionAdapter 提交，避免重复建设生成队列。

准备工具不自行加入生成引用、不自动替换用户选择的模型、不产生文档变更。调用语言模型或付费识别服务产生的成本仍按主方案计入预算。

| 配方                             | 方法                                                       | 适用范围                                         |
| -------------------------------- | ---------------------------------------------------------- | ------------------------------------------------ |
| generate_character_scene         | 角色参考与场景文字分别编译到已验证模型输入                 | 根据角色图生成新场景                             |
| generate_background_reference    | 背景参考与文字要求编译为生成输入                           | 参考场景生成新画面，不承诺原像素保持             |
| generate_character_background    | 角色与背景作为独立角色输入                                 | 支持并验证对应参考组合的模型                     |
| place_character_composite        | 已完成的独立角色合成产物放入背景，必要时在允许区域处理融合 | 保留现有角色像素和姿势，接受拼接与融合的实际限制 |
| insert_character_into_background | 基于指定背景，在用户确定范围内生成角色并合成保护区         | 模型支持局部编辑，保护区可通过确定性合成验证     |

优先选择满足约束且总成本较低的路线。希望保持角色像素并改变姿势时，复用像素的合成路线不适用。只有生成需要的背景或编辑区域确实更便宜时，才能说明节省了成本。

主体与背景不能先拼成一张参考图，再宣称分别控制了身份与场景。如果选定模型只支持一种参考角色，返回 CAPABILITY_UNSUPPORTED，并说明缺少的组合能力。可以展示替代路线和费用，但必须由用户选择，不静默更换模型或丢弃背景。

## 5 能力声明与输入生命周期

ModelCapability 增加 background 角色，并分别验证 subject、background、subject+background、subject+background+composition，以及多 entityId 的组合。验证记录绑定模型或工作流版本、适配器、参考数量、尺寸和测试集合。

图片数量足够不代表模型能分辨每张图片的用途。配方编译器必须按照 Provider 实际接口传递角色或经过验证的输入结构，不能只把图片堆入请求后将任务标记为受支持。

上传图片与已提交的独立角色、背景或合成产物可以作为 Artifact 保存。识别蒙版和未提交笔画仍为临时会话数据，不缓存或用于恢复旧选区。用户退出识别会话后，需要临时区域的生成路线等待重新标记；复用已完成的独立合成产物不等于恢复识别蒙版。

裁切、缩放、去背景、合成都产生新 Artifact，保留来源关系，不原地修改用户素材。临时裁切视图只用于检查时按现有临时视图规则管理。严格保护区检查绑定同一目标尺寸、色彩约定与无损输出，不能对全图重新生成承诺逐像素保持。

## 6 效果检查

验收分别回答角色是否保留、背景要求是否实现，以及用户要求的动作和位置是否完成。

| 检查       | 比较内容                               | 失败或无法判断时                     |
| ---------- | -------------------------------------- | ------------------------------------ |
| 角色身份   | 每个 entityId 的稳定参考与候选角色     | 标出不确定或差异，等待修改或明确接受 |
| 特征保留   | 服装、配饰、标志和用户指定细节         | 按约束报告，不用整图相似度代替       |
| 背景遵循   | 场景地标、布局、透视和光照要求         | 展示对应证据与限制                   |
| 目标完成   | 动作、位置、比例、遮挡、互动           | 未实现则不能只凭身份相似通过         |
| 保护区     | 已定义编辑范围之外的像素               | 程序检查失败则阻止普通正式化或写入   |
| 多角色归属 | 角色数量、参考对应、动作与特征是否混淆 | 明确报告串角色或遗漏，不能隐去失败项 |

正式结果重新检查，不假定低成本预览与正式版一致。角色一致性和场景相似属于待评测能力，不在验证前承诺固定通过率或完全不偏移。

## 7 任务示例

```json
{
  "taskKind": "generateImage",
  "characters": [
    {
      "entityId": "character_a",
      "name": "角色 A",
      "subjectType": "character",
      "referenceIds": ["ref_character_front", "ref_character_side"],
      "preserve": ["identity", "accessories"],
      "requestedAction": "站在门口，右手提着旅行包"
    }
  ],
  "background": {
    "referenceId": "ref_background",
    "mode": "reference",
    "preserve": ["landmarks", "lighting"]
  },
  "prompt": "角色 A 位于前景，保留背景中建筑的主要特征和傍晚光线",
  "outputSize": { "width": 1024, "height": 1024 }
}
```

这是 Runtime 解析后的拟议任务协议，不是通用 Provider 的现成请求。实际是否可以执行，仍取决于对应角色组合、参考数量和生成路线的验证结果。原图和背景不被修改，最终落位需要单独写入批准。

## 8 实施与验收

角色图、背景图的引用与数据协议先纳入设计；真实生成按照验证通过的组合逐项开放。是否将单角色参考生成提前纳入首期，需要结合实际 Provider 能力调整阶段范围，不能把完整多角色能力默认标记为首期可用。

| ID       | 场景                         | 必须观察到的结果                               |
| -------- | ---------------------------- | ---------------------------------------------- |
| GENREF01 | 只提供角色图与明确文字要求   | 身份与允许变化要求明确，支持时生成一份预览     |
| GENREF02 | 只提供背景图                 | reference 与 preserve 语义明确，不虚构主体参考 |
| GENREF03 | 同时提供角色与背景           | 两种引用独立传递，未验证组合则拒绝提交         |
| GENREF04 | 同一角色多图或多个角色       | entityId 对应明确，含糊时补充输入              |
| GENREF05 | 指定模型缺少组合能力         | 返回缺口，不丢弃引用、不自动换模型             |
| GENREF06 | 保持原像素但要求改变姿势     | 识别约束冲突，不用合成路线假装完成             |
| GENREF07 | 临时识别会话失效             | 不恢复蒙版，依赖区域的路线等待重新标记         |
| GENREF08 | 生成过程修改参考素材         | 原输入可追溯，旧结果不自动采用新素材或覆盖源图 |
| GENREF09 | 多角色特征混淆               | 验收按 entityId 报告，不仅返回整图相似分数     |
| GENREF10 | 用户接受效果但未批准文档写入 | 产物保留，原角色、背景与文档对象不变           |

确认合并后，更新主方案第 3、5、8、9、10、13、15、23 和 24 节的引用规则、任务协议、能力组合、配方、质量检查和验收。当前主文档保持不变。
